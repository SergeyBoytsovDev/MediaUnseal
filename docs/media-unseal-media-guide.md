# Медиасправочник Media Unseal

Содержание для будущего встроенного справочника. Основа: аудит возможностей от 28 октября 2026 года для проекта и локального FFmpeg 9.0.2. Пометка **подтверждено** означает реализованный маршрут, проверенный кодом и тестами; реальный файл всё равно зависит от своей структуры и FFmpeg. **Кандидат** — вариант из динамического каталога, для которого программа проверяет сочетание перед работой. **Только FFmpeg** — возможность установленной сборки, для которой нет подтверждённого сценария приложения. Создание короткого GIF из видео дополнительно **подтверждено пользователем вручную** в текущем интерфейсе.

## 1. Возможности Media Unseal

### 1.1. Обзор возможностей

Media Unseal анализирует один локальный медиафайл, показывает его потоки и помогает сохранить выбранные видео, аудио, субтитры и некоторые изображения отдельными файлами. Можно отметить несколько потоков одного источника. Исходный файл не изменяется.

Для поддерживаемого потока доступно копирование без перекодирования. Для видео, аудио и текстовых субтитров возможна конвертация в формат, найденный у установленного FFmpeg; конкретное сочетание проверяется пробным выводом. Результат зависит от кодека, контейнера и сборки FFmpeg.

### 1.2. Извлечение видео без звука

Добавьте файл, дождитесь анализа и отметьте в таблице видеопоток. Аудиодорожки оставьте невыбранными, выберите папку и нажмите «Извлечь». Программа создаёт отдельный файл с выбранным видео, не добавляя к нему звук.

При копировании H.264, HEVC, AV1 и FFV1 подтверждён выход MKV; VP8 и VP9 — WebM; MPEG-2 — M2V; MPEG-4 Part 2 и многокадровый MJPEG — AVI; ProRes — MOV. Для другого контейнера потребуется успешная проверка копирования или конвертация.

### 1.3. Извлечение аудиодорожек

Отметьте одну или несколько звуковых дорожек, например разные языки, укажите папку и нажмите «Извлечь». Каждая дорожка сохраняется отдельно. Если нужен другой звуковой формат, выберите его в «Формат аудио», при необходимости откройте «Настроить», затем нажмите «Применить» и запустите конвертацию. Для озвучки можно отметить сразу несколько языковых аудиодорожек и включить «Разбивать по языкам (создать подпапки)».

Подтверждённые выходы без перекодирования: AAC, MP3, FLAC, Opus, Vorbis, AC-3, E-AC-3, DTS, некоторые PCM и ALAC. Выходное расширение зависит от кодека: например, AAC обычно получает `.aac`, ALAC — `.m4a`.

### 1.4. Извлечение субтитров

В таблице отметьте нужную дорожку субтитров. SubRip сохраняется как SRT, ASS — ASS, WebVTT — VTT, а PGS — SUP без перекодирования. Для текстовых субтитров программа может предложить конвертацию в другой текстовый формат.

PGS и другие графические субтитры состоят из изображений. Превращения их в текст нет: распознавание символов (OCR) не реализовано. При смене текстового формата часть оформления может потеряться.

### 1.5. Конвертация видео

Выберите видеопоток и выходной формат видео. В основной панели показаны распространённые MP4, MKV, MOV, AVI и WebM, если их обнаружила текущая сборка FFmpeg; расширенное окно содержит другие кандидаты. Через «Настроить» можно выбрать кодировщик и параметры.

Конвертация декодирует исходный поток и создаёт новый. Пробный вывод проверяет выбранное сочетание, но не гарантирует успех для любого длинного или необычного файла. Если важны исходное качество и скорость, сначала рассмотрите копирование.

### 1.6. Конвертация аудио

Для отмеченной аудиодорожки выберите формат аудио: среди популярных вариантов могут быть MP3, WAV, FLAC, AAC, AC3, OGG и Opus. «Настроить» позволяет задать кодировщик, битрейт, качество, частоту и число каналов при поддержке выбранного способа.

Форматы с потерями уменьшают объём ценой необратимого изменения звука. FLAC сохраняет звук без потерь; WAV обычно содержит несжатый PCM. Перевод файла с потерями в FLAC не восстанавливает утраченную информацию.

### 1.7. Преобразование субтитров

Для текстовой дорожки выберите «Формат субтитров», например SRT, ASS или WebVTT; после настройки нажмите «Применить» и запустите конвертацию. Расширенный каталог может показывать и другие текстовые выходы, обнаруженные FFmpeg.

Разные форматы хранят разные свойства: SRT подходит для простых реплик, ASS — для сложного оформления. После преобразования проверьте время и внешний вид субтитров. Графические дорожки в текст программа не преобразует.

### 1.8. Изображения и обложки

Анализ различает видеопотоки, статичные изображения и обложки. Подтверждённые JPEG и PNG можно извлечь из подходящего потока или вложения MKV. Предпросмотр сначала пытается показать обложку, а затем кадр видео через FFmpeg.

Распознавание WebP, BMP, TIFF и других графических форматов не означает наличие отдельного экспорта или редактора изображений. Для изображения ограничен размер предпросмотра; повреждённое или неоднозначное вложение может не открыться.

### 1.9. GIF и другие анимированные форматы

Создание короткого GIF из видео через текущий интерфейс **подтверждено пользователем вручную**. Отметьте видеопоток, откройте «Настроить» рядом с «Формат видео», найдите GIF в «Выходной контейнер / формат», нажмите «Применить» и запустите конвертацию. Это практический сценарий, а не обещание поддержки любой длительности, качества палитры и набора исходных файлов.

GIF, APNG и анимированный WebP программа может распознать при анализе. Отдельный мастер анимации, настройка палитры и экспорт уже существующих анимационных входных потоков не подтверждены. APNG, WebP и AVIF в каталоге FFmpeg остаются кандидатами или возможностями самой сборки.

### 1.10. Пакетная обработка дорожек

Можно выбрать несколько потоков **одного** файла. Для каждого создаётся свой результат; общий формат и настройки задаются по типу потока. При совместимом копировании программа может объединить запуск обработки, но выходные файлы остаются раздельными.

Импорт сразу нескольких исходных файлов и объединение разных дорожек в один новый медиафайл не предусмотрены. Для другого источника его нужно добавить отдельно.

## 2. Работа с программой

### 2.1. Первый запуск и FFmpeg

При запуске программа проверяет FFmpeg и FFprobe. FFprobe нужен для анализа, FFmpeg — для большинства операций и предпросмотра. Собственный модуль C# дополнительно читает и копирует подтверждённые вложения JPEG/PNG из Matroska. Если внешние инструменты не найдены, обработка блокируется.

Откройте настройки и укажите пути к установленным инструментам либо воспользуйтесь предусмотренной установкой. После проверки добавьте файл. Наличие инструмента ещё не означает, что в его сборке есть каждый формат или кодировщик.

### 2.2. Добавление и анализ файла

Нажмите «Выбрать файл» для одного локального файла в диалоге или перетащите его в главное окно. Анализ запускается автоматически: FFprobe определяет контейнер и перечисляет потоки, длительность, кодеки и доступные параметры.

Расширение файла служит подсказкой, а фактическое содержимое определяет FFprobe. При смене файла устаревший анализ и предпросмотр отменяются. Если файл не читается, проверьте сам файл и журнал.

### 2.3. Таблица медиапотоков

Таблица показывает отдельные потоки: видео, аудио, текстовые или графические субтитры, статичные изображения и вложения. Индекс обозначает позицию потока внутри источника; язык и название берутся из его метаданных, если они есть.

Смотрите на тип и кодек, а не только на название файла. Неизвестный визуальный поток программа не считает обычным видео автоматически. Это помогает избежать неверной конвертации обложки или анимации.

### 2.4. Выбор дорожек

Отметьте нужные строки таблицы или используйте переключатель «Выбрать все потоки или снять выбор», если нужны все доступные потоки. Перед запуском проверьте, что выбраны именно нужные языки и типы. Без выбранных потоков кнопка обработки не запускает задачу.

Выбор нескольких дорожек создаёт несколько отдельных файлов. Общий выходной формат задаётся отдельно для видео, аудио и субтитров.

Например, для монтажа без исходного звука отметьте только видеопоток. Для озвучки на двух языках отметьте обе нужные аудиодорожки и включите «Разбивать по языкам (создать подпапки)»: программа сохранит отдельный файл для каждой.

### 2.5. Папки и имена файлов

По умолчанию результаты помещаются в системную папку загрузок. Кнопкой «Обзор» можно выбрать другую существующую абсолютную папку, включить папку с именем исходного файла и группировку аудио и субтитров по языку.

Имя результата включает источник, тип, индекс, язык, название и расширение. Недопустимые символы заменяются, совпадения получают номер, существующие файлы не перезаписываются. Перед запуском проверьте свободное место и выбранную папку.

### 2.6. Настройки видео

Выберите видеовыход и откройте «Настроить». Доступны кодировщик, CRF при его поддержке, битрейт в Кбит/с, ширина и высота, частота кадров FPS. Пустое поле не навязывает соответствующий параметр FFmpeg.

В окне «Расширенные настройки конвертации» сначала выберите «Выходной контейнер / формат», затем «Кодировщик» и нужные параметры. Для дополнительных вариантов есть «Найти другие совместимые кодировщики» и «Найти доступные аппаратные кодировщики». Завершите настройку кнопкой «Применить».

Уменьшение разрешения обычно сокращает объём и детализацию. Изменение FPS меняет число кадров в секунду; оно не создаёт новую информацию между исходными кадрами. Не каждый кодировщик принимает одинаковые настройки.

### 2.7. Настройки аудио

Через «Настроить» задаются кодировщик, битрейт, качество, частота дискретизации и число каналов. Пустые поля оставляют выбор FFmpeg. Слишком высокий битрейт для уже сжатого источника не улучшит исходный звук.

Если нужны все исходные особенности дорожки, выбирайте копирование без перекодирования. Если устройство требует конкретный формат, сначала выберите его и проверьте результат на целевом устройстве.

### 2.8. Настройки субтитров

Выберите формат для текстовых субтитров и при необходимости откройте «Настроить». Для простых реплик удобен SRT, для оформления — ASS, для веб-видео — WebVTT. Доступность зависит от FFmpeg.

PGS можно сохранить как SUP. Параметры текстовой конвертации к PGS не применяются: без OCR изображения букв не становятся текстом.

### 2.9. Процесс, отмена и журнал

Нажмите основную кнопку «Извлечь» или «Конвертировать» и следите за общим и текущим прогрессом. Точный процент возможен, когда известна длительность. По окончании можно открыть папку результатов.

Нажмите «Отменить», чтобы остановить задачу: программа останавливает работу и очищает созданные ею временные файлы. Журнал показывает ход и ошибки; отдельный диагностический отчёт помогает разобраться с неудачной операцией. Если один формат не сработал, проверьте сообщение и попробуйте совместимый вариант.

### 2.10. Настройки приложения

В настройках задаются пути к FFmpeg/FFprobe, оформление и другие общие параметры. Доступны пять тем. Реализован русский язык; остальные языки интерфейса пока отмечены как недоступные.

Переключатель сохранения метаданных управляет переносом исходных тегов при экспорте. Это не редактор тегов. Отключённая настройка будущего извлечения вложений MKV не мешает уже доступному извлечению показанных JPEG/PNG.

### 2.11. Типичные ошибки

Если анализ не начинается, проверьте путь к FFprobe, доступ к файлу и целостность источника. Если обработка заблокирована, проверьте также FFmpeg и папку назначения. Без выбора дорожек задача не запускается.

Если пробный вывод отверг формат или кодировщик, выберите другое сочетание либо копирование в подтверждённый контейнер. Если субтитры графические, сохраните их как графический файл; текстовую конвертацию для них программа не выполняет.

## 3. Контейнеры и форматы файлов

### 3.1. Что такое контейнер

Контейнер — структура файла, в которой хранятся потоки и метаданные. MP4, MKV и MOV — контейнеры; H.264 и AAC — кодеки потоков внутри них. Расширение файла лишь обозначает предполагаемый контейнер.

Один контейнер принимает не любые кодеки. При копировании программа проверяет допустимость сочетания; при конвертации создаёт поток с новым кодеком. Поэтому переименование `.mkv` в `.mp4` само по себе ничего не преобразует.

### 3.2. MP4 и MOV

MP4 часто используют для воспроизведения на телефонах и в браузерах, MOV — в монтажных сценариях. Популярный видеокаталог показывает их при наличии в установленном FFmpeg. В аудите подтверждено копирование ProRes в MOV; другие сочетания требуют проверки.

Если исходный поток не подходит выбранному контейнеру, программа может предложить конвертацию. После обработки проверьте файл в нужном плеере или редакторе: успешное создание файла не гарантирует поддержку конкретным устройством.

### 3.3. MKV / Matroska

MKV — расширение контейнера Matroska, способного хранить разные потоки и вложения. Подтверждены выходы без перекодирования для H.264, HEVC, AV1 и FFV1 в отдельный MKV с одним видеопотоком.

Media Unseal также имеет собственный ограниченный модуль для подтверждённых JPEG/PNG вложений MKV. Он копирует исходные байты картинки, а не перекодирует видео или весь контейнер.

### 3.4. AVI и WebM

AVI встречается в старых коллекциях; подтверждено копирование MPEG-4 Part 2 и MJPEG-видео в AVI. WebM рассчитан на совместимые веб-кодеки; для VP8 и VP9 подтверждён маршрут в WebM.

Для других потоков эти контейнеры — кандидаты конвертации, если их предлагает FFmpeg и проходит пробный вывод. Выбор расширения сам по себе не определяет качество или совместимость.

### 3.5. Другие контейнеры

## 4. Видео- и аудиокодеки

### 4.1. Что такое кодек

Кодек описывает способ кодирования видео, звука или субтитров; кодировщик — конкретную программу или устройство, создающее такой поток. Например, H.264 — кодек, `libx264` — его программный кодировщик. Декодер читает входной поток.

Media Unseal не предлагает выбор декодера: чтение входа выполняет FFmpeg. Доступные кодировщики меняются вместе со сборкой FFmpeg, драйверами и оборудованием.

### 4.2. H.264 / AVC

H.264 — распространённый видеокодек. Его можно скопировать без перекодирования в отдельный MKV. При конвертации конкретный кодировщик выбирается из доступных вариантов, например `libx264` или проверенный аппаратный вариант.

Имена `h264_nvenc`, `h264_amf`, `h264_qsv` и другие обозначают разные реализации одного кодека. Наличие имени в FFmpeg не гарантирует доступность оборудования или успешную обработку любого файла.

### 4.3. H.265 / HEVC

HEVC помогает получать меньший файл при сопоставимом визуальном качестве, но совместимость с устройствами различается. Подтверждён маршрут копирования HEVC в MKV; конвертация зависит от найденного кодировщика и контейнера.

В локальном FFmpeg перечислены `libx265` и аппаратные реализации HEVC. Проверяйте пробный вывод и воспроизведение на целевом устройстве.

### 4.4. AV1, VP8, VP9

AV1, VP8 и VP9 — современные видеокодеки, часто используемые для сетевого видео. Подтверждённое копирование AV1 идёт в MKV, VP8 и VP9 — в WebM. Это сохраняет исходный поток без изменения качества.

Для нового кодирования FFmpeg может предлагать программные и аппаратные реализации, но их сочетания с выбранным контейнером проверяются отдельно. Кодирование AV1 может требовать заметного времени.

### 4.5. MPEG-4 Part 2 и другие

MPEG-4 Part 2, включая ASP, не равен MP4: первый — кодек, второй — контейнер. Подтверждён выход такого видеопотока в AVI без перекодирования. MPEG-2 можно сохранить как M2V, ProRes — как MOV, FFV1 — как MKV.

Для редких кодеков смотрите каталог в теме «Другие кодеки». Запись кодировщика в FFmpeg показывает потенциальную возможность сборки, а не подтверждённый маршрут приложения.

### 4.6. AAC, MP3, Opus

Это форматы звука с потерями. AAC, MP3 и Opus имеют подтверждённые отдельные выходы без перекодирования. Opus обычно подходит для современного сетевого аудио, MP3 широко совместим со старым оборудованием.

При конвертации выбирайте формат под устройство или площадку. Повторное кодирование уже сжатого звука может добавить искажения даже при высоком битрейте.

### 4.7. AC3, E-AC3, DTS

Эти кодеки часто встречаются в многоканальном звуке. Их можно сохранить без перекодирования в отдельные `.ac3`, `.eac3` и `.dts` соответственно. Так сохраняется исходная структура потока.

Конвертация в иной формат зависит от кодировщика и может изменить каналы или совместимость. Если нужен оригинальный звук, выбирайте копирование.

### 4.8. FLAC, PCM и WAV

FLAC сжимает звук без потерь; подтверждён отдельный выход FLAC. PCM хранит несжатые отсчёты. Для конкретных PCM s16/s24/s32/f32 little-endian подтверждён WAV.

WAV — контейнер, а не единый кодек. Не любой вариант PCM автоматически проходит подтверждённый маршрут; сверяйте формат исходного потока и результат проверки.

## 5. Технологии обработки

### 5.1. Копирование без перекодирования

Копирование переносит сжатый поток в отдельный совместимый файл без изменения его изображения или звука. Это полезно, когда нужен оригинальный поток и подходит выходной контейнер.

{{diagram:stream-copy}}

Программа указывает конкретный индекс потока и режим копирования FFmpeg. Совместимость проверяется для выбранного контейнера; неудачное сочетание не исправить простым переименованием файла.

### 5.2. Декодирование и кодирование

При конвертации FFmpeg сначала читает исходный поток, затем кодировщик создаёт новый и muxer записывает контейнер. Так можно изменить формат, размер кадра, FPS или параметры звука.

{{diagram:transcode}}

Повторное кодирование с потерями может снизить качество. Выбирайте его, когда действительно нужен иной формат или параметры.

### 5.3. Программные кодировщики

Программный кодировщик работает на процессоре. Примеры из локальной сборки: `libx264`, `libx265`, `libaom-av1`, `libsvtav1`, `libmp3lame`, `libopus`. Их доступность зависит от установленного FFmpeg.

В расширенном окне базовый список содержит неаппаратные варианты для кодека по умолчанию; «Найти другие совместимые кодировщики» проверяет дополнительные. Один кодек может иметь несколько программных реализаций с разными параметрами.

### 5.4. Аппаратные кодировщики

Кнопка «Найти доступные аппаратные кодировщики» проверяет варианты вроде NVENC, QSV, AMF, VAAPI, VideoToolbox, Vulkan и D3D12VA коротким пробным выводом. Результат относится к текущей машине и сборке FFmpeg.

Само имя аппаратного кодировщика не гарантирует, что конкретная видеокарта выполнит всю задачу. Аппаратное декодирование и GPU-фильтры как универсальный пользовательский режим сейчас не реализованы. `h264_mf` присутствует как отдельная реализация, но текущий поиск не относит её к аппаратной кнопке.

### 5.5. Битрейт и качество

Битрейт — количество данных в секунду. Обычно увеличение битрейта увеличивает размер файла и может уменьшить видимые или слышимые потери, но не восстанавливает уже потерянные детали.

CRF задаёт целевое качество для кодировщиков, которые его поддерживают; итоговый размер заранее неизвестен. Для аудио могут применяться битрейт или параметр качества. Пустые поля оставляют выбор FFmpeg.

### 5.6. Разрешение и FPS

Разрешение — ширина и высота кадра в пикселях. FPS — частота кадров. При конвертации можно задать масштаб и FPS; при копировании исходные параметры сохраняются.

Уменьшение обычно сокращает объём, а увеличение не добавляет исходных деталей. Изменение FPS может дублировать или удалять кадры, поэтому проверьте плавность результата.

### 5.7. Частота дискретизации и каналы

Частота дискретизации показывает, сколько звуковых отсчётов записано за секунду. Число каналов определяет моно, стерео и многоканальный звук.

В настройках аудиоконвертации можно задать частоту и число каналов. Уменьшение числа каналов меняет пространственный звук; увеличение не создаёт новых независимых записанных каналов.

### 5.8. Метаданные и языки

FFprobe читает теги, язык и название потока, когда они есть. Эти сведения помогают выбрать дорожку и входят в безопасное имя результата; аудио и субтитры можно разложить по языковым папкам.

Переключатель «Сохранять метаданные» определяет перенос исходных тегов при экспорте. Media Unseal не предоставляет полноценного редактирования тегов. Если язык не задан в источнике, программа не может достоверно определить его по содержимому.

### 5.9. Собственный модуль вложений Matroska (MKV)

Собственный модуль C# находит раздел вложений Matroska/EBML, проверяет смещения и сопоставляет имя, MIME и порядок вложений с данными FFprobe. Подтверждённые JPEG/PNG он копирует исходными байтами; для предпросмотра читает их с ограничением размера.

{{diagram:matroska-attachments}}

Это не декодер или кодировщик видео и не универсальный разборщик MKV. Если вложение повреждено, неоднозначно или выходит за допустимые границы, модуль останавливает операцию. Проверка выполнена на синтетических MKV; совместимость с любыми реальными крупными файлами не доказана.

### 5.10. Как устроены FFmpeg и FFprobe

FFprobe анализирует файл и сообщает потоки, кодеки, параметры и метаданные. FFmpeg выполняет большинство копирований, конвертацию и получение кадра для предпросмотра. Media Unseal управляет этими инструментами и показывает результат в интерфейсе.

{{diagram:components}}

При первом запуске оба инструмента проверяются. Каталог выходов и кодировщиков считывается из текущего FFmpeg, поэтому на другой машине он может отличаться. Пробный вывод уточняет совместимость выбранного сочетания, но не гарантирует успех на каждом исходнике.

## 6. Справочные материалы

### 6.1. Основные термины

**Поток** — отдельные видео, звук, субтитры или изображение внутри файла. **Контейнер** — способ упаковать потоки; **расширение** — часть имени файла. **Кодек** задаёт представление потока, **кодировщик** создаёт его, **декодер** читает. **Muxer** записывает структуру выходного контейнера.

**Копирование** сохраняет кодек потока; **конвертация** создаёт новый поток. **Битрейт** — объём данных за секунду, **FPS** — кадров за секунду, **метаданные** — теги и служебные сведения. **OCR** — распознавание текста на изображении; в программе его нет.

### 6.2. Расширения файлов

Распространённые контейнеры видео: `.mp4`, `.mkv`, `.mov`, `.avi`, `.webm`. Звуковые выходы: `.aac`, `.mp3`, `.flac`, `.opus`, `.ogg`, `.ac3`, `.eac3`, `.dts`, `.wav`, `.m4a`. Субтитры: `.srt`, `.ass`, `.vtt`, `.sup`. Обложки: `.jpg`, `.png`.

Расширение не доказывает внутренний кодек и не гарантирует воспроизведение. Если файл переименован неправильно, ориентируйтесь на анализ FFprobe и фактический результат.

### 6.4. Частые вопросы

**Можно извлечь сразу несколько языков?** Да, отметьте нужные аудио или субтитровые потоки одного файла; каждый получится отдельно. **Можно объединить их в один новый фильм?** Такой сценарий не предусмотрен.

**Почему формат есть в списке, но не работает?** Список строится по установленному FFmpeg; реальная пара кодировщик–контейнер и конкретный источник должны пройти проверку. **Можно получить текст из PGS?** Нет, OCR нет. **Можно сделать GIF?** Короткий GIF из видео был успешно создан пользователем через текущий интерфейс; широкий набор анимационных сценариев не проверен.

### 6.5. Ограничения программы

Программа обрабатывает один исходный файл за раз и сохраняет выбранные потоки отдельными файлами. Нет универсального экспорта изображений, OCR, отдельного экспорта уже существующих анимационных входных потоков и универсальных настроек аппаратного декодирования/GPU-фильтров.

Динамический каталог зависит от установленного FFmpeg. Аудит фиксирует 66 видеовыходов, 85 аудиовыходов и 8 выходов субтитров, прошедших условия разбора в одной локальной сборке; их работа с каждым кодировщиком и реальным файлом не проверялась. На других системах набор может отличаться.

### 6.6. Развитие проекта

Проект может развиваться с учётом обратной связи и результатов проверок на реальных файлах. Если операция не удалась, полезно сообщить формат источника, выбранные настройки и диагностический отчёт без личных данных. Сроки будущих возможностей не обещаются.

Универсальная система аппаратного декодирования, GPU-фильтров и расширенного аппаратного ускорения рассматривается только как дальнейший план обновлений **после версии 1.0**. В текущих возможностях программы её нет.
