# Медиасправочник Media Unseal

Медиасправочник помогает использовать возможности Media Unseal осознанно: от выбора нужных потоков и выходного формата до проверки качества и совместимости результата. Здесь собраны практические инструкции, объяснения контейнеров и кодеков, а также сведения о технологиях обработки. Выберите интересующую тему в содержании или начните с обзора.

## 1. Возможности Media Unseal

### 1.1. Обзор

Media Unseal даёт точный контроль над потоками медиафайла. После анализа можно выбрать конкретное видео, аудиодорожки, субтитры или доступные изображения и сохранить их отдельными файлами. Программа показывает кодеки, параметры и метаданные потоков, чтобы решение принималось по содержимому файла, а не по его расширению.

В основе работы — два режима. **Копирование без перекодирования** сохраняет исходный поток и подходит, когда нужен оригинальный материал: видеодорожка для монтажа, звук для дальнейшей обработки или субтитры без изменения формата. **Конвертация** создаёт новый поток с выбранными параметрами. Она полезна, когда результат должен соответствовать требованиям редактора, плеера или площадки. Доступность конкретного сочетания кодировщика и выходного формата зависит от установленного FFmpeg и проверяется программой.

Можно обработать сразу несколько потоков одного исходного файла. Например, сохранить две версии озвучки и дорожку субтитров, разложив результаты по языковым папкам. Каждый выбранный поток получает собственный выходной файл; исходник остаётся без изменений. Процесс сопровождается журналом и допускает отмену.

Этот справочник отвечает на два типа вопросов. Раздел **«Работа с программой»** помогает настроить и выполнить операцию. Разделы о контейнерах, кодеках и технологиях объясняют, почему выбранный способ работает, от чего зависит совместимость и какие параметры действительно влияют на результат. Так можно не только получить нужный файл, но и осознанно выбрать способ его создания.

### 1.2. Извлечение видео без звука

Извлечение позволяет сохранить видеопоток отдельным файлом без звукового сопровождения и без перекодирования. Media Unseal копирует исходные видеоданные в подходящий выходной контейнер: кодек, разрешение, частота кадров и качество изображения не меняются. Исходный файл остаётся нетронутым.

Добавьте файл и дождитесь анализа. В таблице потоков поставьте галочку **в первом столбце слева** от нужной видеодорожки. Выбрать поток можно и двойным щелчком по его строке; повторный двойной щелчок снимет выбор. Убедитесь, что аудиодорожки не отмечены.

В панели настроек оставьте для **«Формат видео»** установленный по умолчанию вариант **«Исходный — без перекодирования»**. Укажите папку назначения или оставьте стандартную, затем нажмите **«Извлечь»** внизу окна. Если отмечено несколько видеодорожек, программа сохранит каждую в отдельный файл — все без перекодирования и без добавления звука.

Выходной контейнер подбирается по кодеку выбранного потока и может отличаться от контейнера исходного файла. Например, H.264 может быть сохранён в MKV, даже если исходником был MP4. При этом сам видеопоток остаётся в исходном виде.

### 1.3. Извлечение аудиодорожек

Извлечение сохраняет выбранную аудиодорожку отдельным файлом без перекодирования. Исходный звуковой поток копируется с его кодеком, частотой дискретизации и числом каналов; видео и другие невыбранные потоки в результат не включаются. Исходный медиафайл не изменяется.

Добавьте файл и дождитесь анализа. В таблице потоков поставьте галочку **в первом столбце слева** от нужной аудиодорожки. Выбрать её можно также двойным щелчком по строке; повторный двойной щелчок снимет выбор. Если нужна только звуковая дорожка, убедитесь, что видео и субтитры не отмечены.

В панели настроек оставьте для **«Формат аудио»** вариант **«Исходный — без перекодирования»**. Укажите папку назначения или оставьте стандартную и нажмите **«Извлечь»** внизу окна. Можно отметить сразу несколько аудиодорожек, например с разной озвучкой: каждая сохранится в отдельный файл без перекодирования. Чтобы разложить результаты по языковым подпапкам, включите **«Разбивать по языкам (создать подпапки)»**.

Выходной контейнер зависит от кодека дорожки и может отличаться от контейнера исходного файла. Например, AAC сохраняется как отдельный файл `.aac`, Opus — `.opus`, а ALAC — `.m4a`. Кодек и звуковые данные при этом остаются исходными.

### 1.4. Извлечение субтитров

Извлечение сохраняет дорожку субтитров отдельным файлом без изменения её содержимого. Это позволяет забрать оригинальные реплики, оформление или графические изображения субтитров для дальнейшей работы. Исходный медиафайл не изменяется.

Добавьте файл и дождитесь анализа. В таблице потоков поставьте галочку **в первом столбце слева** от нужной дорожки субтитров. Её можно выбрать и двойным щелчком по строке; повторный двойной щелчок снимет выбор. Если требуются только субтитры, оставьте видео и аудио неотмеченными.

В панели настроек оставьте для **«Формат субтитров»** вариант **«Исходный — без перекодирования»**. Укажите папку назначения или оставьте стандартную, затем нажмите **«Извлечь»** внизу окна. При выборе нескольких дорожек каждая сохранится отдельно. Для дорожек с разными языками можно включить **«Разбивать по языкам (создать подпапки)»**.

Тип выходного файла определяется исходной дорожкой: SubRip сохраняется как `.srt`, ASS — `.ass`, WebVTT — `.vtt`, графические PGS — `.sup`. PGS состоит из изображений, поэтому извлечение не превращает его в редактируемый текст; распознавание символов программой не выполняется.

### 1.5. Конвертация видео

Конвертация нужна, когда видео требуется сохранить в другом выходном формате или подготовить для определённого редактора, плеера либо площадки. Media Unseal проверяет совместимость исходного видеопотока с выбранным контейнером. Если поток подходит, его можно перенести без изменения; если нет, программа создаёт новый поток подходящим кодировщиком. Перекодирование обычно занимает больше времени, зато позволяет получить файл с нужным сочетанием формата и кодека.

Добавьте файл и дождитесь анализа. В таблице потоков отметьте видеодорожку галочкой **в первом столбце слева** или двойным щелчком по строке. В панели настроек откройте **«Формат видео»** и выберите нужный вариант, например AVI или MP4. Укажите папку назначения либо оставьте стандартную. После проверки выбранного формата нажмите кнопку запуска внизу окна: **«Обработать»**, если требуется перекодирование, или **«Извлечь»**, если все выбранные потоки можно перенести без него.

Если отмечено несколько видеопотоков одного файла, каждый будет сохранён отдельно в выбранном выходном формате. Программа проверит совместимость каждого потока: одним может хватить переноса в новый контейнер, другим потребуется перекодирование. Например, при выборе AVI для потоков с разными кодеками результат обработки каждого может отличаться по способу создания. Исходный файл при этом не меняется.

Кнопка **«Настроить»** позволяет выбрать кодировщик и параметры обработки. Выбранная там настройка применяется ко всем отмеченным видеопотокам. Если для разных дорожек нужны **разные кодировщики**, обработайте их по очереди, каждый раз выбирая нужную дорожку и её настройки. Подробно эти параметры разобраны в статье **«Настройки видео»**.

### 1.6. Конвертация аудио

Конвертация аудио помогает подготовить звуковую дорожку для плеера, редактора или другого способа использования: например, сохранить её как MP3, FLAC или WAV. Media Unseal проверяет выбранный выходной формат и подбирает подходящий кодировщик из установленного FFmpeg. Если исходный поток совместим с новым контейнером, программа может перенести его без перекодирования; иначе создаст новый звуковой поток. Перекодирование обычно требует больше времени и может изменить звук, особенно при переходе между форматами с потерями.

Добавьте файл и дождитесь анализа. Отметьте нужную аудиодорожку галочкой **в первом столбце слева** или двойным щелчком по её строке. В панели настроек откройте **«Формат аудио»** и выберите нужный вариант. Укажите папку назначения или оставьте стандартную, затем нажмите кнопку внизу окна: **«Обработать»** при перекодировании либо **«Извлечь»**, если программа может сохранить поток без него.

Если выбрано несколько аудиодорожек одного файла, каждая получит отдельный результат в выбранном выходном формате. При необходимости включите **«Разбивать по языкам (создать подпапки)»**. Программа проверяет совместимость дорожек по отдельности, поэтому способ обработки может различаться даже при одном общем выходном формате.

Через **«Настроить»** можно выбрать кодировщик и параметры звука для отмеченных дорожек. Если каждой дорожке нужны свои настройки, обработайте их по очереди. Значение битрейта, частоты и каналов подробно объясняется в статье **«Настройки аудио»**.

### 1.7. Преобразование субтитров

Субтитры можно сохранить в исходном виде или преобразовать в другой текстовый формат. Media Unseal работает с каждой выбранной дорожкой отдельно: например, SubRip можно сохранить как SRT, а текстовые субтитры при совместимости преобразовать в ASS или WebVTT. Разные форматы поддерживают разное оформление, поэтому после преобразования стоит проверить время реплик и внешний вид результата.

Добавьте файл и дождитесь анализа. Отметьте нужную дорожку субтитров галочкой **в первом столбце слева** или двойным щелчком по её строке. Для простого извлечения оставьте в **«Формат субтитров»** исходный вариант и нажмите **«Извлечь»**. Для преобразования выберите нужный текстовый формат, укажите папку назначения или оставьте стандартную и запустите обработку кнопкой внизу окна. Она покажет **«Обработать»**, если потребуется конвертация, либо **«Извлечь»**, если поток можно сохранить без неё.

Можно отметить несколько дорожек одного файла: каждая сохранится отдельно. Если субтитры на разных языках, при необходимости включите **«Разбивать по языкам (создать подпапки)»**. Выбранный выходной формат применяется к отмеченным текстовым дорожкам; для разных форматов обработайте их по очереди.

Графические субтитры, например PGS, можно извлечь в исходном виде как файл `.sup`. Программа не распознаёт текст на изображениях, поэтому преобразовать PGS в SRT или другой текстовый формат она не может. Подробнее о различии текстовых и графических дорожек рассказано в статье **«Настройки субтитров»**.

### 1.8. Изображения и обложки

Анализ различает видеопотоки, статичные изображения и обложки. Подтверждённые JPEG и PNG можно извлечь из подходящего потока или вложения MKV. Предпросмотр сначала пытается показать обложку, а затем кадр видео через FFmpeg.

Распознавание WebP, BMP, TIFF и других графических форматов не означает наличие отдельного экспорта или редактора изображений. Для изображения ограничен размер предпросмотра; повреждённое или неоднозначное вложение может не открыться.

### 1.9. GIF и другие анимированные форматы

Создание короткого GIF из видео через текущий интерфейс **подтверждено пользователем вручную**. Отметьте видеопоток, откройте «Настроить» рядом с «Формат видео», найдите GIF в «Выходной контейнер / формат», нажмите «Применить» и запустите конвертацию. Это практический сценарий, а не обещание поддержки любой длительности, качества палитры и набора исходных файлов.

GIF, APNG и анимированный WebP программа может распознать при анализе. Отдельный мастер анимации, настройка палитры и экспорт уже существующих анимационных входных потоков не подтверждены. APNG, WebP и AVIF в каталоге FFmpeg остаются кандидатами или возможностями самой сборки.

### 1.10. Вложения MKV

В контейнере MKV могут находиться не только медиапотоки, но и вложенные файлы: обложки, шрифты субтитров и другие материалы. Media Unseal обнаруживает их при анализе и показывает в таблице отдельной строкой **«Вложения»**. Программа читает вложения собственным модулем Matroska и сохраняет их исходные данные без перекодирования.

Чтобы выбрать файлы по отдельности, щёлкните правой кнопкой по строке **«Вложения»** и откройте **«Просмотр»**. В окне «Вложения MKV» видны имена, типы и размеры файлов. Поставьте галочки слева от нужных вложений и закройте окно. Выбранные файлы останутся в общем выборе: укажите папку назначения и нажмите **«Извлечь»** внизу главного окна. Так вложения можно обработать вместе с выбранными дорожками.

Если нужны **все** вложения, нажмите кнопку выбора слева в их строке. После этого они также войдут в общий запуск. Есть и отдельная команда: щёлкните правой кнопкой по строке «Вложения» и выберите **«Извлечь все»**. Она сразу запускает извлечение всех вложений MKV, независимо от выбора остальных дорожек.

Вложения сохраняются как отдельные файлы. Программа проверяет их расположение внутри MKV и не перезаписывает уже существующие результаты.

### 1.11. Обработка нескольких дорожек

Media Unseal позволяет подготовить несколько результатов за один запуск. Можно отметить отдельные строки таблицы или нажать кнопку **«Выбрать все потоки или снять выбор»** в заголовке первого столбца. Она выбирает все доступные для обработки потоки текущего файла, включая вложения MKV, если они обнаружены.

Проверьте выбор перед запуском. Для видео, аудио, субтитров, изображений и анимаций в панели настроек предусмотрены свои поля формата: например, видео можно направить в один формат, а аудио — в другой. Если отмечено несколько потоков **одного типа**, выбранный для этого типа формат применяется ко всем. Когда двум аудиодорожкам нужны разные выходные форматы или настройки, обработайте их по очереди.

Укажите папку назначения или оставьте стандартную. При необходимости включите папку с названием исходного файла и языковые подпапки для аудио и субтитров. Затем нажмите кнопку запуска внизу окна. Её надпись зависит от выбранной обработки: **«Извлечь»** для копирования без перекодирования или **«Обработать»**, если хотя бы один поток будет конвертирован.

Каждый поток и каждое выбранное вложение сохраняются отдельным файлом. В ходе работы можно следить за прогрессом и журналом или остановить задачу кнопкой **«Отменить»**. Такой общий запуск относится к потокам **одного исходного файла**.

## 2. Работа с программой

### 2.1. Первый запуск и FFmpeg

При запуске Media Unseal проверяет два внешних инструмента: **FFprobe** анализирует файл и сообщает сведения о его потоках, а **FFmpeg** выполняет большинство операций извлечения, преобразования и создания предпросмотра. Для чтения и копирования вложений MKV в программе есть также собственный модуль Matroska. Пока проверка FFmpeg и FFprobe не пройдена, обработка медиафайлов недоступна.

Если оба инструмента найдены и отмечены как готовые, дополнительная настройка не нужна — можно сразу добавлять файл. Если одного из них не хватает, откройте **«Настройки» → «Установщик FFmpeg»**. Там отдельно показано состояние FFmpeg и FFprobe. Воспользуйтесь доступным вариантом установки или кнопками **«Указать путь FFmpeg»** и **«Указать путь FFprobe»**, если инструменты уже установлены. При ручном выборе указывайте сами исполняемые файлы, а не папку с ними.

После установки или смены путей нажмите **«Проверить повторно»**. Когда появится сообщение **«Все компоненты готовы»**, программа сможет анализировать и обрабатывать файлы. Выбранные пути сохраняются; если позднее перенести или удалить инструменты, их потребуется указать заново.

Набор доступных выходных форматов и кодировщиков определяется установленной сборкой FFmpeg. Поэтому при работе на другом компьютере список вариантов может отличаться, даже если версия Media Unseal та же.

### 2.2. Добавление и анализ файла

В Media Unseal можно открыть локальный видео- или аудиофайл, отдельный файл субтитров, изображение либо анимацию. Программа не отсекает файлы по короткому списку расширений: она проверяет их фактическое содержимое. Поэтому необычное расширение само по себе не мешает анализу, но успешное открытие зависит от возможностей установленного FFprobe и состояния файла.

Чтобы добавить источник, нажмите **«Выбрать файл»** и укажите его в диалоге либо перетащите файл в окно программы. За один раз выбирается **один** локальный файл; несколько файлов одним перетаскиванием не добавляются. После выбора анализ начинается автоматически — отдельную кнопку запуска нажимать не нужно.

FFprobe определяет контейнер и перечисляет найденные потоки: их типы, кодеки, длительность и доступные параметры, названия и языки. Media Unseal на основе этих сведений заполняет таблицу, различает обычное видео, изображения и анимации, а для MKV при наличии признаков вложений дополнительно проверяет их собственным модулем Matroska. Анализ только изучает источник: извлечение и конвертация начнутся после выбора потоков и запуска обработки.

Время анализа может различаться из-за структуры и состояния файла, количества потоков и вложений, а также скорости доступа к источнику — например, с локального диска или сетевого хранилища. Один лишь размер файла не даёт надёжной оценки. При выборе другого источника незавершённый анализ прежнего отменяется. Если файл не открылся, проверьте сообщение программы и **«Журнал событий»**: причиной может быть повреждение файла или отсутствие поддержки его содержимого в текущем FFprobe.

### 2.3. Таблица медиапотоков

Таблица заполняется после анализа файла. Каждая строка представляет найденный поток: видео, аудио, субтитры, изображение или анимацию. Появляются только те типы, которые действительно обнаружены в источнике. Если в MKV найдены вложенные файлы, для них добавляется отдельная строка **«Вложения»**. Неизвестный визуальный поток программа не выдаёт за обычное видео: его тип и доступность определяются отдельно.

| Столбец | Что показывает |
|---|---|
| Выбор слева | Галочка добавляет поток к обработке. Кнопка в заголовке выбирает все доступные потоки или снимает выбор. Недоступный поток выбрать нельзя. |
| Тип | Видео, аудио, субтитры, изображение, анимация или другой распознанный тип. У MKV может быть отдельная строка «Вложения». |
| Индекс | Номер потока внутри исходного файла. У общей строки вложений индекса нет. |
| Язык | Язык из метаданных потока. Если он не указан, стоит «—»; программа не определяет язык по звучанию или тексту. |
| Кодек | Формат самого потока и, если известен, его профиль. Контейнер файла и кодек — разные вещи. |
| Битрейт | Скорость передачи данных потока, если FFprobe смог её сообщить. Прочерк означает отсутствие сведений, а не нулевой битрейт. |
| Каналы / Разрешение | Для аудио — число каналов, для видео и изображений — размеры кадра; для субтитров — текстовый или графический тип. Недоступные сведения показаны прочерком. |
| Статус | Текущая возможность обработки или состояние уже запущенной операции. |

Чтобы выбрать отдельную строку, поставьте галочку слева или дважды щёлкните по строке; повторное действие снимет выбор. Щелчок правой кнопкой по обычному потоку открывает команду **«Свойства»** с более подробными параметрами и метаданными. Это окно предназначено для просмотра, а не для изменения потока. У строки **«Вложения»** по правой кнопке доступны **«Просмотр»** для выбора отдельных файлов и **«Извлечь все»**; подробности описаны в статье **«Вложения MKV»**.

**Статус нужно читать вместе с выбранным форматом.** До запуска он показывает, что программа может сделать с потоком; после запуска — ход и результат обработки:

| Статус | Что означает и что делать |
|---|---|
| **Доступен** | Для потока есть путь извлечения без перекодирования. Его можно выбрать. |
| **Доступна конвертация** | Готового пути извлечения в исходном виде нет, но поток можно преобразовать после выбора подходящего формата и настройки. |
| **Нужна настройка** | Поток выбран, однако действительного плана обработки пока нет: проверьте формат, кодировщик или сообщение об ошибке настройки. |
| **Конвертация** | Для выбранного потока настроено преобразование; обработка ещё не началась. |
| **Извлекается / Конвертируется** | Операция выполняется сейчас. |
| **Извлечён / Сконвертирован** | Операция для этого потока завершилась успешно. |
| **Ошибка / Отменено** | Обработка не завершилась успешно; подробности ищите в сообщении строки и журнале событий. |
| **Недоступен** | Для потока нет доступного пути извлечения или преобразования. Его галочка неактивна. |

Наведите указатель на ячейку **«Статус»**, чтобы увидеть более подробное сообщение, особенно при недоступности или ошибке настройки. У общей строки вложений вместо обычного статуса показано число найденных файлов. Статус «Доступен» говорит о наличии маршрута обработки, но итоговая работа с конкретным файлом зависит и от его состояния.

### 2.4. Папки и имена файлов

**Куда попадут результаты.** В блоке настроек экспорта проверьте поле **«Папка для сохранения»**. При первом запуске программа предлагает системную папку загрузок, если она доступна; выбранный вами путь запоминается для следующих запусков. Нажмите **«Обзор»**, чтобы выбрать другую папку, или впишите путь в поле и нажмите Enter. Введённый путь также принимается при переходе к другому элементу окна. Папка должна уже существовать и быть доступной для записи: если проверка не пройдёт, программа покажет ошибку и вернёт прежний путь. Пока введённый текст не подтверждён, начать обработку нельзя.

**Как разложить файлы.** Без дополнительных флажков все результаты сохраняются прямо в выбранной папке. Флажок **«Создавать папку с названием исходного файла»** помещает их в новую или уже существующую подпапку с именем источника без расширения. Флажок **«Разбивать по языкам (создать подпапки)»** раскладывает аудио и субтитры по папкам, названным согласно языку в метаданных; для потока без указанного языка создаётся папка «язык не указан». Видео, изображения и анимации остаются в общей папке. Если включены оба флажка, папки языков создаются *внутри* папки источника.

**Как формируется имя.** Для обычного потока программа соединяет имя исходного файла без расширения, тип потока, его индекс и, если они есть, язык и название из метаданных. Расширение соответствует выбранному выходному формату. Например, аудиопоток с языком ru получит имя по схеме источник_audio_индекс_ru_название.расширение; отсутствующие поля пропускаются. Вложения MKV сохраняются под их собственными именами. Недопустимые для имени файла символы заменяются, а слишком длинные имена сокращаются.

**Если такое имя уже есть.** Существующий файл не перезаписывается: к имени нового добавляется номер в скобках, например источник_audio_1 (2).mka. Это правило действует и при повторной обработке того же источника. После завершения нажмите **«Открыть папку»** внизу окна: откроется выбранная основная папка, из которой можно перейти в созданные подпапки. Перед длительным преобразованием проверьте путь и свободное место на диске.

### 2.5. Настройки видео

Выберите видеопоток галочкой слева в таблице. В блоке настроек экспорта можно сразу выбрать **«Формат видео»**; кнопка **«Настроить»** открывает окно **«Расширенные настройки конвертации»** для более точного выбора. В нём сначала задайте **«Выходной контейнер / формат»** — тип итогового файла, затем **«Кодировщик»** — способ сжатия видеопотока. Это разные параметры: один контейнер может допускать несколько кодеков, но не любую их комбинацию. Список зависит от установленного FFmpeg. Кнопка **«Найти другие совместимые кодировщики»** проверяет дополнительные варианты для выбранного формата, а **«Найти доступные аппаратные кодировщики»** — варианты, доступные на данном компьютере. Появление кодировщика в списке ещё не гарантирует успешное кодирование конкретного источника.

Поля ниже — **необязательные**. В каждом можно выбрать предложенное число или ввести своё; пустое поле с подсказкой «Автоматически» не задаёт этот параметр вручную. Укажите только то, что хотите изменить:

| Настройка | Что она меняет и о чём помнить |
|---|---|
| **Качество / CRF** | Управляет качеством при сжатии, если выбранный кодировщик поддерживает CRF: для многих распространённых программных кодировщиков меньшее число означает меньше потерь и обычно больший файл. Это не процент качества и не универсальная шкала для всех кодировщиков. Если поле неактивно, выбранный кодировщик не подтвердил поддержку CRF. |
| **Битрейт, Кбит/с** | Задаёт целевой объём видеоданных за секунду. Более высокий битрейт часто увеличивает размер файла и может лучше сохранять детали, но не исправляет дефекты исходника. Итоговый размер и качество зависят также от длительности, сложности кадров и работы кодировщика; число не гарантирует точный размер файла. Обычно начните с одного способа управления качеством — CRF или битрейта — и оцените результат. |
| **Ширина и высота, пикс.** | Меняют размер кадра при перекодировании. Если заполнено только одно поле, программа просит FFmpeg рассчитать другое с сохранением пропорций; конкретный размер может быть округлён под требования кодировщика. Уменьшение размеров убирает часть деталей, увеличение не восстанавливает отсутствующие детали. Если вручную задать обе величины в другом соотношении, изображение может растянуться или сжаться. |
| **Частота кадров, кадр/с** | Задаёт частоту *выходных* кадров. При снижении частоты FFmpeg убирает лишние кадры, при повышении может повторять соседние: новые движения между кадрами от этого не появляются. Поэтому перевод 60 в 30 кадр/с может сделать движение менее плавным, а перевод 25 в 60 не превращает исходник в съёмку 60 кадр/с. Для обычного сохранения движения оставьте поле пустым. |

Если для исходного видеопотока выбран **«Исходный»** и параметры не заданы, доступное копирование сохраняет его без перекодирования. Для смены качества, размера или частоты кадров нужен кодировщик и перекодирование. Флажок **«Кодировать принудительно»** появляется в ситуациях, когда программа могла бы скопировать поток с тем же кодеком: включите его, если требуется именно новый проход кодирования. После выбора нажмите **«Применить»** — программа проверит сочетание формата, кодировщика и параметров. Настройка действует на все выбранные видеопотоки; при разных требованиях к ним обрабатывайте потоки отдельно.

### 2.6. Настройки аудио

Отметьте нужную аудиодорожку, выберите **«Формат аудио»** и нажмите **«Настроить»**. В окне задаются **«Выходной контейнер / формат»** и **«Кодировщик»**. Формат определяет тип файла, кодировщик — представление звука внутри него. Программа предлагает подходящий вариант, а кнопка **«Найти другие совместимые кодировщики»** позволяет проверить дополнительные. Поля аудио также допускают выбор числа из списка или ручной ввод; пустые остаются на усмотрение FFmpeg.

| Настройка | Что она меняет и о чём помнить |
|---|---|
| **Битрейт, Кбит/с** | Определяет объём данных, выделяемый на секунду сжатого звука. При прочих равных более высокий битрейт обычно требует больше места и может уменьшить потери, но повторное кодирование уже сжатой записи не возвращает утраченные детали. Подходящее число зависит от кодировщика, числа каналов и требований устройства. |
| **Качество, 0–10** | Передаёт кодировщику отдельный параметр качества. Это **не оценка исходной дорожки по десятибалльной шкале**: значение и даже направление влияния зависят от выбранного кодировщика. Некоторые кодировщики могут не поддерживать этот режим. Если нет конкретной причины задавать число, оставьте поле пустым; при выборе проверяйте итоговый файл на слух и по сообщению о совместимости. |
| **Частота, Гц** | Задаёт частоту дискретизации выходного звука: сколько отсчётов сигнала приходится на секунду. При её изменении FFmpeg пересчитывает отсчёты. Понижение может отрезать верхнюю часть частотного диапазона; повышение не создаёт звуковых деталей, которых не было в источнике. Частоту обычно меняют ради требований формата или устройства. |
| **Каналы** | Задаёт число выходных каналов: например, 1 — моно, 2 — стерео, 6 — многоканальный звук. При уменьшении числа каналов FFmpeg сводит их, и исходное пространственное разделение уже не сохранится; увеличение числа каналов само по себе не создаёт независимые новые записи. Учитывайте возможности воспроизводящего устройства. |

Для сохранения исходного кодирования и числа каналов оставьте **«Исходный — без перекодирования»** и не задавайте параметры преобразования. В окне может быть доступен **«copy»**: это копирование звука в выбранный контейнер, которое программа отдельно проверяет на совместимость. При кодировании с тем же исходным кодеком флажок **«Кодировать принудительно»** позволяет потребовать повторное кодирование. Нажмите **«Применить»**; проверка может отклонить неподдерживаемое сочетание. Выбранные настройки аудио применяются ко всем отмеченным аудиодорожкам, поэтому разные параметры для разных языков задавайте отдельными запусками.

### 2.7. Настройки субтитров

Отметьте текстовый поток субтитров и откройте **«Настроить»** рядом с **«Формат субтитров»**. В окне есть два основных поля: **«Выходной контейнер / формат»** определяет тип файла, **«Кодировщик»** — способ записи субтитров в этот файл. В отличие от видео и аудио, здесь нет полей битрейта, качества, размера кадра или частоты: программа не настраивает внешний вид и тайминги отдельными числовыми параметрами. Для выбранного формата кнопка **«Найти другие совместимые кодировщики»** может проверить дополнительные варианты; при исходном формате субтитров поиск недоступен. Если появляется флажок **«Кодировать принудительно»**, он требует повторной записи текста вместо доступного копирования. После выбора нажмите **«Применить»**; программа проверит доступность сочетания в установленном FFmpeg.

Ориентируйтесь на назначение файла. **SRT** удобен для обычного текста и широко поддерживается, **ASS** сохраняет больше возможностей оформления, **WebVTT** рассчитан на веб-среду. Перевод в более простой формат может потерять стили, позиционирование и другие особенности исходных субтитров; проверьте результат в проигрывателе, где будете его использовать. Если нужен исходный вид без преобразования, оставьте **«Исходный — без перекодирования»**.

Графические субтитры, например PGS, состоят из изображений надписей. Окно текстовой конвертации не распознаёт буквы на этих изображениях и не превращает их в SRT или ASS. Для такого потока используйте доступное извлечение в исходном графическом виде, например PGS в SUP. Если отмечено несколько текстовых потоков, выбранный формат применяется к каждому отдельному выходному файлу; учитывайте возможные различия в их оформлении.

### 2.8. Процесс, отмена и журнал

**Запуск и ход работы.** После выбора потоков, выходных форматов и папки нажмите основную кнопку внизу окна. Она называется **«Извлечь»**, когда выбранные потоки можно сохранить без перекодирования, и **«Обработать»**, когда хотя бы один из них нужно конвертировать. «Обработать» здесь означает запуск преобразования; если в том же наборе есть потоки для простого извлечения, они не перекодируются только из-за названия кнопки. Обычные выбранные потоки сохраняются отдельными файлами; строка вложений MKV может дать несколько файлов. Во время работы строка состояния сообщает, какой поток сейчас извлекается или конвертируется, а в таблице меняется статус его строки.

Полоса внизу окна показывает общий ход задачи, рядом могут появляться процент текущего потока и прошедшее время. Если у источника нет надёжных сведений о длительности или FFmpeg ещё не сообщил позицию, точный процент временно недоступен — это само по себе не ошибка. При нескольких потоках программа показывает их продвижение по очереди; завершение одного файла не означает завершения всей задачи. По окончании проверьте итоговое сообщение и статусы строк: очередь может завершиться полностью, с ошибками у отдельных потоков или после отмены. Кнопка **«Открыть папку»** ведёт в выбранную основную папку результатов.

**Отмена.** Нажмите **«Отменить»**, чтобы остановить текущую обработку и оставшуюся очередь. Уже полностью сохранённые файлы остаются в папке назначения; незавершённый результат не выдаётся за готовый. Программа удаляет созданные ею временные файлы и временную папку обработки. Если очистке помешала ошибка доступа или изменение пути, это отмечается в диагностике — при необходимости проверьте папку вручную. У остановленных и ещё не начатых потоков появится соответствующий статус; их можно выбрать и запустить повторно.

**Журнал событий** находится в главном окне. Это короткая история понятных пользователю сообщений: проверка FFmpeg и FFprobe, начало и итог анализа, найденные вложения MKV, начало извлечения или конвертации, завершение отдельных потоков, отмена и ошибки. В каждой строке показано время. Цвет помогает быстро найти результат:

| Подсветка | Что искать |
|---|---|
| Зелёная | Успешно завершённое действие, например сохранённый поток. |
| Жёлтая | Предупреждение или отмена: прочитайте текст, чтобы понять, требуется ли ваше действие. |
| Красная | Ошибка анализа, настройки или обработки; начните разбор с этого сообщения. |
| Без цветового акцента | Обычное сообщение о ходе работы, ещё не означающее успех или ошибку. |

Журнал удобен для быстрой проверки: какой поток завершился, какой не удалось обработать и на каком этапе возникло предупреждение. На экране остаются последние **200** пользовательских сообщений. Кнопка **«Очистить»** над журналом убирает их только из этого списка; сохранённую историю диагностики она не стирает.

**Diagnostic Report.** Нажмите **«Сохранить лог»** над журналом: сначала откроется окно **«Диагностический отчёт»**. Там можно просмотреть более подробные записи, сгруппированные по датам и запускам программы: время, английскую категорию операции, уровень **INFO / WARN / ERROR** и техническое сообщение. Уровни выделены цветом; внизу показано количество событий, предупреждений и ошибок. Это место для разбора причин, которые не поместились в краткий журнал, включая сведения о проверках совместимости и сбоях FFmpeg.

В окне отчёта нажмите **«Сохранить»**, чтобы записать его в текстовый файл. Если сообщаете разработчику об ошибке или замечании, опишите источник, выбранные настройки и наблюдаемый результат; при необходимости приложите этот файл после просмотра его содержимого. Отчёт не отправляется программой автоматически. Кнопка **«Очистить»** *в окне отчёта* удаляет сохранённую диагностическую историю. Она хранится с ограничением по времени и объёму, поэтому для давней ошибки лучше сохранить отчёт сразу после её появления.

### 2.9. Настройки приложения

Откройте **«Настройки»** кнопкой с шестерёнкой в верхней части главного окна. Слева расположены разделы **«Установщик FFmpeg»**, **«Оформление»**, **«Язык интерфейса»**, **«База знаний»** и **«О программе»**. Выберите раздел, чтобы увидеть его параметры справа. Изменения оформления, языка и масштаба применяются при выборе и сохраняются для следующих запусков; отдельной кнопки «Сохранить настройки» нет. Эти параметры меняют работу с интерфейсом, но не кодируют файлы заново и не меняют уже сохранённые результаты.

**Оформление.** В разделе **«Оформление»** выберите одну из пяти карточек темы. Цветные образцы справа помогают сравнить фон, панели, акцент и текст до выбора. Различаются плотность и визуальный характер рабочего окна:

| Тема | Как выглядит |
|---|---|
| **Studio Dark** | Контрастный студийный стиль; тема по умолчанию. |
| **Resolve Workspace** | Более плотная рабочая среда. |
| **Adobe Clean Pro** | Спокойная типографика и увеличенные отступы. |
| **Industrial Utility** | Строгое утилитарное оформление. |
| **Hybrid Modern Panel** | Мягкие панели и холодный цветовой акцент. |

Тема применяется сразу: можно последовательно попробовать несколько вариантов и оставить удобный. Выделенная карточка показывает текущий выбор. Это настройка цветов и подачи элементов; доступные форматы, работа FFmpeg и параметры экспорта от неё не зависят.

**Масштаб интерфейса.** Под карточками тем находится список **«Масштаб интерфейса»**. Режим **«Автоматически»** подбирает размер элементов с учётом экрана. Если текст и кнопки кажутся слишком мелкими или крупными, выберите фиксированный масштаб от **75% до 125%** с шагом 5%. Он меняет размер элементов окон программы, а не разрешение видео или масштаб будущего файла. Выбор действует сразу и запоминается. На небольшом экране фактический размер окна может дополнительно ограничиваться свободным местом, поэтому заданные 125% не всегда означают, что окно сможет занять именно столько пространства.

**Язык интерфейса.** В разделе **«Язык интерфейса»** показаны карточки языков. Нажмите доступную карточку или её переключатель: выбранный язык применяется к подписям и сообщениям без отдельного подтверждения и сохраняется. Активная карточка выделена; приглушённые карточки с неактивным переключателем выбрать нельзя. Наличие языка в списке само по себе не означает, что он уже доступен в конкретной установленной сборке. Эта настройка не определяет язык аудиодорожек или субтитров исходного файла.

**Установщик FFmpeg и база знаний.** Раздел **«Установщик FFmpeg»** показывает состояние необходимых компонентов и позволяет вернуться к их проверке или настройке путей. Порядок действий при первом запуске описан в статье **«Первый запуск и FFmpeg»**; здесь не требуется повторно настраивать исправно работающие инструменты. В разделе **«База знаний»** кнопка **«Открыть справочник»** открывает медиасправочник.

**О программе и обновления.** Здесь показаны версия приложения, сведения о разработчике и используемых компонентах. Кнопка **«Проверить обновление»** запускает реальную проверку: рядом появится состояние проверки, сообщение о последней версии, о найденной новой версии либо об ошибке проверки. Если обновление доступно, появляется кнопка **«Скачать и обновить»**; возможность автоматической установки зависит от способа установки и платформы, а при необходимости программа предложит ручной путь. Во время обработки файла обновление запускать нельзя — дождитесь завершения задачи. Проверка новой версии сама по себе ничего не устанавливает.

В этом же разделе есть ссылка **«Поддержать разработчика»**: она открывает отдельное окно с доступными способами добровольной поддержки проекта.

### 2.10. Типичные ошибки

Если операция не удалась, сначала прочитайте **«Статус»** нужной строки таблицы и наведите на него указатель: там может быть более точная причина. Затем посмотрите красное или жёлтое сообщение в **«Журнале событий»**. Для подробностей откройте **«Сохранить лог» → «Диагностический отчёт»**. Ошибка одного потока не обязательно означает, что не сохранились остальные: проверьте итог каждой строки и папку результатов.

**Файл не открывается или обработка не запускается**

| Что видно | Что проверить |
|---|---|
| **FFmpeg или FFprobe не найдены, программа не готова к работе** | Откройте **«Настройки» → «Установщик FFmpeg»**, проверьте состояние обеих утилит и их пути, затем нажмите **«Проверить повторно»**. Для анализа нужен FFprobe, для большинства операций обработки — FFmpeg. |
| **«Файл не найден» или «Нет доступа к файлу»** | Убедитесь, что источник не был перемещён или удалён, доступен из вашей учётной записи и не находится на отключённом носителе. Выберите его заново. |
| **«Не удалось запустить FFprobe»** | Повторите проверку компонентов в установщике. Наличие пути ещё не означает, что исполняемый файл запускается. |
| **«Файл может быть повреждён или не поддерживается»** | Попробуйте открыть его в другом проигрывателе и проверьте, завершилось ли его копирование или загрузка. FFprobe может не прочитать повреждённый файл либо содержимое, которое не поддерживает установленная сборка. Одно только расширение не доказывает формат. |
| **«FFprobe не ответил вовремя»** | Повторите анализ; для файла на сетевом или медленном носителе попробуйте локальную копию. Если проблема повторяется только с этим источником, сохраните диагностический отчёт. |
| **«Анализ отменён» после выбора другого файла** | Незавершённый анализ прежнего источника прекращается при смене файла. Дождитесь окончания анализа нового; это сообщение само по себе не говорит о повреждении прежнего. |
| **Нет миниатюры, но потоки обнаружены** | Неудача предпросмотра не равна неудаче анализа или извлечения. Ориентируйтесь на тип и статус потока в таблице; подробности сбоя предпросмотра есть в журнале и отчёте. |
| **Кнопка «Извлечь» или «Обработать» неактивна** | Дождитесь конца анализа и проверки форматов, отметьте доступный поток галочкой слева, проверьте выбранную папку и отсутствие статуса **«Нужна настройка»**. Пока хотя бы один выбранный поток не имеет действительного плана обработки, запуск заблокирован. |

**Поток виден, но формат не подходит**

| Что видно | Что проверить |
|---|---|
| **«Недоступен», галочка потока не ставится** | Программа не нашла для него доступного пути извлечения или преобразования. Наведите указатель на статус. Смена расширения исходного файла не добавит поддержку его содержимого. |
| **«Доступна конвертация» или «Нужна настройка»** | Для исходного сохранения нет готового маршрута либо выбранное преобразование ещё не настроено. Выберите выходной формат, откройте **«Настроить»** и проверьте кодировщик; ориентируйтесь на сообщение конкретной строки. |
| **«Исходный кодек нельзя скопировать в выбранный контейнер»** | Контейнер и кодек несовместимы для копирования. Выберите другой выходной контейнер либо кодировщик для перекодирования. Простое переименование файла не помогает. |
| **«Нет подходящего кодировщика» или проверка не создала пробный файл** | Попробуйте другой формат или кодировщик из списка. Кнопка **«Найти другие совместимые кодировщики»** проверяет дополнительные варианты, но результат зависит от установленного FFmpeg. Не считайте любой кодировщик, перечисленный FFmpeg, пригодным для каждого контейнера. |
| **«Введите числовые значения или оставьте поля пустыми»** | В окне **«Настроить»** исправьте поле с буквами, недопустимым разделителем или слишком большим числом. Пустое поле означает автоматический выбор; введённое значение должно попадать в допустимый диапазон. |
| **Не удаётся скопировать видео без перекодирования в выбранный формат** | Причиной может быть кодек, профиль, частота кадров, разрешение, формат цвета или структура исходного потока. Прочитайте конкретное сообщение о совместимости: иногда достаточно другого контейнера, иногда требуется перекодирование. При ошибках временных меток или заголовков откройте Diagnostic Report. |
| **Графические субтитры не преобразуются в SRT или ASS** | PGS и другие графические субтитры содержат изображения текста. Программа не выполняет OCR; используйте доступное извлечение в графическом виде, например PGS в SUP. |
| **Поиск аппаратных кодировщиков ничего не нашёл или завершился ошибкой** | Такая проверка относится к выбранному формату и текущей системе. Используйте доступный программный кодировщик либо проверьте состояние аппаратного ускорения и FFmpeg; отсутствие найденного варианта не блокирует все преобразования. |

**Сохранение, результат и журнал**

| Что видно | Что проверить |
|---|---|
| **«Папка сохранения не найдена» или «Недопустимый путь»** | Укажите существующую папку через **«Обзор»** или исправьте путь в поле и подтвердите его Enter. Если папка была удалена после выбора, выберите её снова. |
| **«Нет доступа к папке» или «Не удалось записать файл»** | Выберите папку, в которую разрешена запись, проверьте свободное место и доступность диска. Если папка находится на внешнем или сетевом носителе, проверьте соединение. Готовые результаты других потоков могут сохраниться. |
| **«Не удалось запустить FFmpeg»** | Вернитесь в **«Установщик FFmpeg»** и выполните повторную проверку. Если путь изменился после запуска программы, укажите действительный исполняемый файл. |
| **Превышено время ожидания обработки** | Посмотрите, какой поток и формат указан в статусе. Повторите попытку с локальным источником и доступной папкой; если сбой воспроизводится, сохраните диагностический отчёт. Время ожидания само по себе не указывает единственную причину. |
| **Не удалось прочитать или извлечь вложение MKV** | Проверьте, что исходный MKV открывается и вложение видно в окне **«Просмотр»**. При ошибке чтения списка остальные потоки могут оставаться доступны; технические детали ищите в Diagnostic Report. |
| **«Очередь завершена с ошибками»** | Это общий итог, а не диагноз каждого файла. Сверьте статусы потоков и журнал: успешно завершённые файлы сохранены, проблемные можно настроить и обработать повторно. |
| **После «Отменить» часть файлов осталась** | Это ожидаемо: полностью готовые файлы сохраняются, незавершённые временные результаты удаляются. Статус **«Не запускалось из-за отмены»** относится к потокам, до которых очередь не дошла. |
| **Выходной файл не виден там, где ожидали** | Нажмите **«Открыть папку»** и проверьте флажки папки источника и группировки по языкам. При совпадении имён программа добавляет номер в скобках, не заменяя прежний файл. |
| **Извлечённое видео без звука** | Отдельный видеопоток сохраняется отдельно от аудиодорожек. Если нужен звук, отметьте аудиопоток для отдельного извлечения; это не признак повреждения видеорезультата. |
| **Не удалось проверить обновления** | Это относится к проверке новой версии, а не к обработке медиафайлов. Повторите её позднее и проверьте доступ к сети; подробность ошибки может быть в диагностическом отчёте. |

Если предложенная проверка не помогла, сохраните **Diagnostic Report** сразу после повторения ошибки. Укажите, какой файл и поток обрабатывали, какой выходной формат и кодировщик выбрали, что ожидали и что произошло. Перед передачей отчёта просмотрите его содержимое.

## 3. Контейнеры и форматы файлов

### 3.1. Что такое контейнер

Контейнер определяет, **как в файле организованы потоки и сведения о них**: где лежат видео, звук и субтитры, как связаны их временные метки, где записаны языки, названия, главы и другие метаданные. Кодек решает другую задачу — как представлены и, возможно, сжаты сами кадры и звуковые отсчёты. Поэтому «видео в MP4» не называет способ сжатия: внутри может быть разный видеокодек. H.264, наоборот, может встретиться в разных контейнерах.

{{diagram:container}}

Файл содержит описание дорожек и блоки данных; часто в нём есть индекс для перехода к нужному времени. Временные метки синхронизируют изображение и звук. Если они повреждены, воспроизведение может идти со сбоями, даже когда кодек поддерживается. Контейнер может разрешать несколько языков, субтитры, главы, обложки или вложения, но **конкретный формат и программа** определяют, какие из этих возможностей действительно доступны.

| Уровень | Что определяет |
|---|---|
| **Контейнер** | Состав файла, расположение потоков, временные метки и метаданные. |
| **Кодек** | Представление видео, звука или субтитров внутри потока. |
| **Расширение** | Предполагаемый формат файла; само по себе не доказывает его содержимое. |
| **Настройки кодирования** | Битрейт, разрешение, качество и другие свойства конкретного потока. |

Форматы появились под разные задачи. AVI и WAV основаны на RIFF; QuickTime и выросшее из него семейство MP4 организуют данные в иерархию блоков; Matroska использует расширяемую структуру EBML; WebM опирается на Matroska, но ограничивает набор кодеков ради веб-доставки. Это объясняет разные привычные сценарии: архив с несколькими дорожками, обмен между устройствами, монтаж или публикация в интернете. [QuickTime](https://developer.apple.com/documentation/quicktime-file-format/atoms), [MP4](https://www.iso.org/standard/79110.html), [Matroska](https://www.matroska.org/technical/basics.html), [WebM](https://www.webmproject.org/about/).

**Контейнер сам по себе не бывает «сжатым с потерями» или «несжатым».** Большой и маленький MP4 могут отличаться кодеком, битрейтом, длительностью и разрешением; WAV часто содержит несжатый PCM, но может содержать и другой звук. Копирование потока в другой допустимый контейнер меняет упаковку без повторного кодирования. Конвертация создаёт новый поток и может изменить качество. Переименование расширения не выполняет ни того, ни другого.

В Media Unseal после анализа посмотрите столбцы **«Тип»**, **«Кодек»** и **«Статус»**. Для сохранения исходного кодирования оставьте **«Исходный — без перекодирования»**. Если нужен другой контейнер, программа проверит допустимость копирования; если оно не подходит, настройте кодировщик. Успешная запись файла не гарантирует воспроизведение на конкретном телевизоре, телефоне или в редакторе — проверяйте результат там, где собираетесь его использовать.

### 3.2. MP4 и MOV

**Один исторический корень.** MOV связан с QuickTime, где дорожки и служебные сведения записываются в иерархию блоков, называемых *atoms*. MP4 вырос из семейства ISO Base Media File Format. Оба контейнера могут хранить видео, звук и метаданные; расширение не сообщает, каким кодеком создан поток. [Структура QuickTime](https://developer.apple.com/documentation/quicktime-file-format/movie_atoms), [стандарт MP4](https://www.iso.org/standard/79110.html).

**MP4** часто выбирают для передачи и воспроизведения: телефоны, браузеры и телевизоры обычно знают этот контейнер. Его сильная сторона — широкая совместимость при подходящем содержимом. Однако корректный MP4 с неподдерживаемым кодеком, профилем, глубиной цвета или звуком всё равно может не открыться. «Сохранить в MP4» не означает «сделать совместимым со всеми устройствами».

**MOV** часто встречается в записи камер и монтажных процессах. Он особенно уместен, когда нужно сохранить профессиональный видеопоток, например ProRes. В Media Unseal подтверждено копирование ProRes в отдельный MOV без перекодирования. Это сохраняет кодек исходного потока, но не делает файл маленьким: размер зависит от самого видео. MOV не означает высокое качество автоматически и может быть менее удобен для целевого устройства, ожидающего MP4.

**Как выбрать.** Если нужен исходный поток, начните с допустимого копирования и проверьте результат. Если устройство требует другой кодек, выберите **«Формат видео»**, затем **«Настроить»** и нужный кодировщик. Перекодирование займёт время и может изменить размер и качество, зато позволяет создать новое сочетание. Media Unseal сохраняет выбранные видеопотоки и аудиодорожки **в отдельные файлы**: извлечённый видеопоток в MP4 или MOV не получает звук автоматически.

После сохранения проверьте длительность, перемотку и воспроизведение целиком. Для передачи файла ориентируйтесь на требования адресата, а не только на расширение или факт успешного экспорта.

### 3.3. MKV / Matroska

Matroska — открытый расширяемый формат; **MKV** — привычное расширение его видеофайла. Название напоминает о вложенной структуре: в одном исходном контейнере могут находиться несколько потоков видео, озвучки и субтитров, языковые метки, главы и вложенные файлы. Техническая основа — EBML. Родственный аудиофайл нередко имеет расширение MKA. [Основы Matroska](https://www.matroska.org/technical/basics.html), [элементы контейнера](https://www.matroska.org/technical/elements.html).

Гибкость удобна для хранения исходников с несколькими языками и сохранения потоков без перекодирования. В Media Unseal подтверждены выходы H.264, HEVC, AV1 и FFV1 в **отдельный MKV с одним видеопотоком**. Программа извлекает выбранные потоки по отдельности; она не собирает из них новый многодорожечный MKV. Такой контейнер не является «без потерь» сам по себе: внутри может быть видео как с потерями, так и без них.

**Вложения** отличаются от временных медиапотоков. Matroska может хранить, например, изображения обложек. В программе их можно открыть через **«Просмотр»**, выбрать по отдельности или нажать **«Извлечь все»**. Собственный модуль на C# читает структуру Matroska и копирует подходящие JPEG/PNG без изменения байтов. Это не кодировщик видео и не универсальный редактор MKV. Иные типы вложений не становятся поддерживаемыми лишь потому, что Matroska вообще умеет их хранить.

MKV разумен, когда важны исходный кодек, несколько дорожек или архивный сценарий. Но конкретный проигрыватель может не понимать отдельный кодек, вид субтитров или вложение. Для передачи другому человеку проверьте итоговый файл в его программе или устройстве.

### 3.4. AVI и WebM

**AVI** — контейнер семейства RIFF, знакомый по старым программам Windows, архивам камер и монтажным файлам. Он содержит описания потоков, данные и индекс для переходов по файлу. Его практическая ценность сегодня часто связана с устройствами или программами, которые ожидают именно AVI; при этом современный кодек не станет понятным старому устройству только из-за смены контейнера. [Структура AVI](https://learn.microsoft.com/en-us/windows/win32/directshow/avi-riff-file-reference).

В Media Unseal подтверждено копирование MPEG-4 Part 2 и MJPEG-видео в AVI. MJPEG хранит кадры как отдельные JPEG-подобные изображения и при сопоставимых условиях нередко требует больше места, чем современные межкадровые кодеки. Но **AVI не означает несжатое видео**: степень сжатия зависит от потока внутри. Для старого устройства уточняйте допустимые кодек, звук, размер и частоту кадров.

**WebM** создан для веб-доставки и основан на Matroska, но имеет более строгие правила содержимого. В программе подтверждено копирование VP8 и VP9 в WebM; для нового вывода динамический каталог проверяет доступные варианты FFmpeg. Типичные звуковые кодеки WebM — Vorbis и Opus. Поддержка кодека в MKV не доказывает его допустимость в WebM. [Описание WebM](https://www.webmproject.org/about/), [правила контейнера](https://www.webmproject.org/docs/container/).

AVI выбирайте под требования старого рабочего процесса, WebM — под подходящие веб-кодеки. Размер и качество обоих определяются кодеком и параметрами, а не названием контейнера. Если копирование в нужный формат отвергнуто, выберите совместимый кодировщик и проверьте результат в целевой среде.

### 3.5. Другие контейнеры

За пределами MP4, MOV, MKV, AVI и WebM программа предлагает ещё несколько **видеоконтейнеров-кандидатов**. Они появляются в списке, когда установленный FFmpeg сообщает о нужном muxer и кодировщике; конкретное сочетание программа дополнительно проверяет. Для исходного видеопотока Media Unseal также умеет сохранять обнаруженный контейнер без перекодирования, если путь копирования применим. Ни один из следующих форматов не «сжимает сильнее» сам по себе — размер задаёт поток внутри.

### 3.6. Аудиоконтейнеры

Аудиофайл тоже имеет **упаковку и содержимое**. WAV — не синоним «идеального звука», а MP3 — одновременно название распространённого кодека и файла с определённой структурой. Звук может быть несжатым, сжатым без потерь или с потерями; выбор контейнера не восстановит детали, уже утраченные в исходной записи. При копировании сохраняется исходный аудиокодек, при конвертации звук декодируется и записывается заново.

| Файл или семейство | Что обычно внутри и зачем выбирать | Что важно при использовании |
|---|---|---|
| **WAV (.wav)** | Контейнер RIFF, часто с несжатым PCM. Удобен для монтажа, обмена с аудиоредактором и совместимости со старой аппаратурой. | PCM обычно занимает много места; WAV может содержать и другие кодеки. Проверьте частоту, разрядность и число каналов, если программа-получатель предъявляет требования. |
| **AIFF (.aif/.aiff)** | Аудиоформат семейства Apple, часто с PCM. Близок WAV по рабочим задачам, но отличается структурой и традиционным окружением. | Смена WAV на AIFF без смены кодека не делает звук «чище». Выбирайте под нужный редактор. |
| **CAF (.caf)** | Гибкий контейнер Core Audio; в Media Unseal для него предусмотрены варианты PCM и ALAC в зависимости от FFmpeg. | Подходит для определённых рабочих процессов Apple; поддержку вне них проверяйте. ALAC сжимает без потерь, PCM обычно хранит отсчёты без такого сжатия. |
| **AU (.au)** | Исторический звуковой формат, встречающийся в старых системах и архивах. | Используйте для совместимости с существующим материалом; не выбирайте по привычке вместо широко принимаемых WAV или FLAC. |
| **M4A (.m4a)** | Аудиоприменение семейства MP4. Часто несёт AAC с потерями либо ALAC без потерь. | Расширение M4A не сообщает, какой из них внутри. Для совместимости устройства смотрите кодек в свойствах потока. |
| **MP3 (.mp3)** | Массовый формат распространения звука со сжатием с потерями и очень широкой поддержкой. | Удобен для прослушивания и передачи, но повторное перекодирование уже сжатого источника не улучшит его качество. |
| **FLAC (.flac)** | Формат со сжатием **без потерь** и собственными блоками метаданных; может содержать обложку. | Обычно заметно экономнее несжатого PCM при сохранении восстановимых отсчётов, но точный выигрыш зависит от материала. Устройство должно поддерживать FLAC. |
| **Ogg (.ogg/.oga)** | Открытый контейнер, способный нести разные аудиопотоки; .ogg часто связан с Vorbis, .oga подчёркивает аудиосодержимое. | Ogg — название упаковки, Vorbis — кодека. По одному расширению нельзя заключить, какой именно звук внутри. |
| **Opus (.opus)** | Файл с потоком Opus в упаковке Ogg; удобен для речи, музыки и передачи с ограниченным битрейтом. | Opus использует сжатие с потерями. Поддержка зависит от проигрывателя, особенно на старых устройствах. |
| **AAC / ADTS (.aac)** | Поток AAC с транспортными заголовками ADTS; это компактная упаковка, отличная от M4A. | Удобен для отдельного извлечения AAC без перекодирования, но обычно несёт меньше привычных сведений о коллекции, чем файл M4A. |
| **AC-3 (.ac3) и E-AC-3 (.eac3)** | Отдельные потоки многоканального звука семейства Dolby. | Часто нужны для сохранения исходной дорожки; проверяйте поддержку конкретного варианта и раскладки каналов на целевом устройстве. |
| **DTS (.dts)** | Отдельный поток многоканального звука DTS. | Может быть востребован домашним кинотеатром, но не всякий плеер или телевизор его декодирует. |
| **Другие контейнеры с аудио** | AVI, MKV, MOV, MP4, WebM и другие видеофайлы тоже могут содержать звуковые дорожки. | Media Unseal извлекает выбранную аудиодорожку **отдельным файлом**; название контейнера источника не обязывает сохранять звук в нём же. |

В текущем интерфейсе каталог аудиоконвертации ограничен поддерживаемыми типами: MP3, WAV, FLAC, AAC/ADTS, AC-3, E-AC-3, DTS, Ogg, Opus, M4A, AIFF, AU и CAF. Показ конкретного выхода зависит от установленного FFmpeg и наличия подходящего кодировщика; программа проверяет выбранное сочетание. Для AAC, MP3, FLAC, Opus, Vorbis, AC-3, E-AC-3, DTS, ряда PCM и ALAC также есть маршруты извлечения без перекодирования. Исходный отдельный аудиофайл некоторых форматов может сохранять свою упаковку. [Формат FLAC](https://datatracker.ietf.org/doc/html/rfc9639), [структура Ogg](https://www.xiph.org/ogg/doc/oggstream.html), [Opus в Ogg](https://datatracker.ietf.org/doc/html/rfc7845).

**Как выбирать.** Для неизменённой дорожки оставьте **«Исходный — без перекодирования»**. Для рабочего несжатого звука часто выбирают WAV с PCM; для экономного хранения без потерь — FLAC или совместимый ALAC; для небольшого файла с широкой поддержкой — MP3 или AAC; для современных приложений — Opus, когда его принимает получатель. Это ориентиры, а не гарантия: проверьте кодек, каналы и результат на нужном устройстве.

### 3.7. Форматы изображений

Формат изображения определяет, как записаны пиксели, цвет, прозрачность и метаданные; некоторые форматы умеют хранить **последовательность кадров**. Главное различие для выбора — сжатие с потерями или без, поддержка прозрачности и возможность анимации. Расширение не гарантирует, что конкретный файл содержит все особенности формата. Media Unseal при анализе различает категории **«Изображение»** и **«Анимация»**: многокадровые GIF, APNG и WebP относятся ко второй, обычный статический PNG — к первой. Частота кадров, которую FFprobe иногда сообщает даже для неподвижной картинки, сама по себе не доказывает анимацию. [Спецификация PNG и APNG](https://www.w3.org/TR/png/), [контейнер WebP](https://developers.google.com/speed/webp/docs/riff_container).

**Основные варианты и их смысл**

| Формат | Свойства и типичный выбор | Что делает текущая программа |
|---|---|---|
| **JPEG / JPG** | Сжимает фотографии с потерями; обычно экономнее несжатого растра, но повторное сохранение может накапливать искажения. Стандартный JPEG не хранит прозрачность. | Распознаёт и извлекает подходящий поток или обложку; JPG есть среди кандидатов статической конвертации при наличии кодировщика FFmpeg. |
| **PNG** | Сжатие без потерь, чёткие края, текст и прозрачность. Хорош для схем, скриншотов и обложек; фотография в PNG нередко крупнее JPEG. | Распознаёт статический PNG как изображение, извлекает подходящий поток или вложение; PNG доступен как кандидат статического выхода. |
| **WebP** | Бывает с потерями и без, поддерживает прозрачность и анимацию. Удобен для веб-графики, когда получатель его понимает. | Статический WebP распознаётся как изображение, анимированный — как анимация. Есть исходное сохранение подходящего потока и кандидаты преобразования; результат зависит от FFmpeg и конкретного файла. |
| **BMP** | Простой растровый формат, часто без эффективного сжатия. Полезен для совместимости со старой графической программой; обычно не лучший выбор для передачи больших изображений. | Распознавание и маршрут исходного извлечения для подходящего потока; кандидат статической конвертации. |
| **TIFF** | Гибкий формат для сканирования, печати и промежуточных материалов: возможны разные схемы сжатия и глубины цвета. Расширение TIFF не обещает ни «несжатый», ни «без потерь» вариант. | Распознавание, исходное извлечение подходящего потока и кандидат статической конвертации. |
| **QOI** | Простой формат растровой графики без потерь. Быстрое кодирование удобно в специальных рабочих процессах, но поддержка у массовых программ уже, чем у PNG. | Распознавание, исходное извлечение подходящего потока и кандидат статической конвертации. |
| **GIF** | Палитра до 256 цветов на кадр, простая прозрачность и покадровая анимация. Для ролика с множеством оттенков GIF часто получается крупным или теряет цвета. | Однокадровый GIF относится к изображениям, многокадровый — к анимациям. Подходящий поток можно сохранить в исходном виде; **создание короткого GIF из видео проверено вручную**. |
| **APNG** | Развитие PNG с покадровой анимацией, полноцветными кадрами и прозрачностью; обычный просмотрщик PNG может показать только неподвижное изображение. | Многокадровый APNG распознаётся как анимация и имеет маршрут исходного извлечения и кандидат преобразования. Обычный PNG без анимационных данных анимацией не становится. |

JPEG и PNG возникли из разных практических задач: JPEG ориентирован на эффективное хранение фотографических изображений, PNG проектировался для переносимой графики без потерь и как альтернатива GIF. GIF сохранил значение благодаря простой анимации; APNG расширил PNG кадрами, а WebP объединил статическую и анимированную графику с несколькими способами сжатия. [История PNG](https://www.libpng.org/pub/png/pnghist.html), [возможности WebP](https://developers.google.com/speed/webp/faq).

**Что именно считать «поддержкой».** Текущий код содержит пути исходного извлечения для подходящих JPEG, PNG, BMP, TIFF, QOI, статических WebP и GIF, а также для GIF, APNG и WebP как анимаций. Выходы статической конвертации JPG, PNG, BMP, TIFF, QOI, WebP и GIF и анимационные GIF, APNG, WebP появляются при наличии нужных muxer и кодировщиков в установленном FFmpeg и проходят проверку выбранного сочетания. Отдельные JPEG/PNG вложения Matroska копируются собственным модулем. **Из многокадровой GIF или другой анимации программа не делает статичную картинку в этой категории**: преобразования анимации сохраняют последовательность кадров либо переводят её в подходящее видео.

### 3.8. Совместимость контейнеров и кодеков

Совместимость — не одно разрешение «да» или «нет». Должны совпасть **четыре условия**: контейнер допускает нужный тип потока; FFmpeg умеет записать выбранный кодек в этот контейнер; Media Unseal имеет подходящий маршрут и успешно проверяет его; устройство или программа-получатель умеет открыть итоговый файл. К ним добавляются свойства самого потока: профиль, цветовой формат, разрешение, частота кадров, число каналов, структура заголовков и временные метки. Поэтому одинаковое расширение у двух файлов не гарантирует одинакового результата. [Форматы и muxer FFmpeg](https://ffmpeg.org/ffmpeg-formats.html).

**Начните с задачи, а не с расширения.** Если важно сохранить исходное качество и кодек, оставьте **«Исходный — без перекодирования»** и посмотрите предложенный файл. Если нужен другой контейнер, попробуйте копирование потока: программа проверит сочетание и при успешной операции не будет сжимать видео или звук заново. Если копирование невозможно или получателю нужен другой кодек, откройте **«Настроить»**, выберите формат и кодировщик, затем примените параметры. Конвертация меняет сами данные потока; сжатие с потерями может ухудшить качество, а увеличение битрейта не восстановит потерянное ранее.

| Исходный поток и подтверждённый маршрут | Почему это полезно | Граница вывода |
|---|---|---|
| **H.264, HEVC, AV1, FFV1 → MKV** | Есть маршрут извлечения видеопотока без перекодирования в отдельный MKV. | Это не обещание, что каждый проигрыватель понимает все четыре кодека. |
| **VP8, VP9 → WebM** | Позволяет сохранить подходящий исходный видеопоток в веб-контейнере. | Поддержка WebM устройством и свойства конкретного потока проверяются отдельно. |
| **ProRes → MOV** | Уместно для сохранения исходного монтажного видеопотока. | Файл может быть большим и не подходить массовому плееру. |
| **MPEG-4 Part 2, MJPEG → AVI** | Практично для старых коллекций и рабочих процессов. | Старое устройство может требовать ещё и конкретные параметры кодека. |
| **MPEG-2 Video → отдельный M2V** | Сохраняет видеопоток без нового кодирования. | M2V — элементарный поток, не обычный многодорожечный видеоконтейнер. |
| **AAC, MP3, FLAC, Opus, Vorbis, AC-3, E-AC-3, DTS, ряд PCM, ALAC → соответствующий аудиовыход** | Позволяет извлечь отдельную дорожку в исходном кодеке. | Упаковка и расширение выбираются по потоку; для другой упаковки может потребоваться проверка копирования. |

Есть также маршрут сохранения исходного контейнера у подходящих отдельных видео- и аудиофайлов. Таблица показывает **базовые подтверждённые пути**, а не все допустимые пары. Динамический каталог конвертации в текущей программе ограничен предусмотренными категориями muxer; длинные списки из разделов 3.5–3.7 относятся к раннему снимку установленного FFmpeg и не расширяют меню автоматически.

**Почему подходящий на вид файл всё-таки отвергается?**

| Ситуация | Что означает и что сделать |
|---|---|
| **Контейнер не принимает исходный кодек** | Копирование невозможно в выбранную упаковку. Выберите другой контейнер или перекодирование с подходящим кодировщиком. |
| **Кодировщик указан FFmpeg, но пробный файл не создаётся** | Наличие имени кодировщика ещё не подтверждает пару «кодировщик + muxer». Попробуйте другой вариант или предусмотренный поиск совместимых кодировщиков. |
| **Не подходит профиль, разрешение, FPS или формат цвета** | Даже допустимый кодек может иметь свойства, которые выбранная упаковка или целевое устройство не принимает. Посмотрите конкретный статус и настройте преобразование нужного параметра. |
| **Ошибки временных меток, заголовков или структуры потока** | Проблема может быть в данных источника, а не в названии формата. Откройте Diagnostic Report; иной контейнер или перекодирование иногда помогает, но успех заранее не гарантирован. |
| **Файл создался, но не играет у получателя** | Запись и воспроизведение — разные проверки. Уточните поддерживаемые кодеки и параметры устройства, затем создайте файл под них. |

**Не смешивайте возможности контейнера и действия программы.** MKV может хранить много дорожек, но Media Unseal сохраняет выбранные дорожки по отдельности; извлечённое видео не содержит выбранный рядом звук. WebM родственен MKV, однако имеет собственные ограничения кодеков. WAV часто содержит PCM, но не всякий WAV несжатый. PNG — формат изображения без потерь, а APNG с анимационными данными представляет отдельный сценарий. Именно сочетание структуры файла, кодека и характеристик потока объясняет совместимость лучше одного расширения.

Для работы с конкретным файлом используйте проверяемый порядок: **анализ → тип и кодек потока → статус → исходное извлечение или настройка формата → проверка результата у адресата**. Если программа сообщает «Нужна настройка» либо «Недоступен», наведите указатель на статус; если пробный вывод или обработка завершились ошибкой, откройте журнал и Diagnostic Report. Таблица совместимости не подменяет эту проверку, потому что установленный FFmpeg и целевое устройство могут отличаться.

## 4. Видео- и аудиокодеки

### 4.1. Что такое кодек

**Кодек** задаёт способ представить изображение или звук в цифровом потоке и восстановить его при воспроизведении. Кодировщик создаёт поток по правилам кодека, декодер читает его. H.264 — название кодека, а libx264 и аппаратный H.264 NVENC — разные кодировщики. MP4, MKV и WAV — контейнеры: они упаковывают потоки, но сами по себе не определяют способ сжатия. Два файла MP4 могут требовать разных декодеров.

Несжатое видео хранит кадры целиком; его объём растёт с разрешением, частотой кадров и глубиной цвета. Несжатый звук хранит отсчёты каждого канала. Кодек уменьшает объём: например, описывает различия между кадрами и движение, предсказывает соседние значения или отбрасывает менее заметные слуху детали. Декодер восстанавливает кадры и звуковые отсчёты для проигрывателя. При сжатии **с потерями** исходные данные целиком не восстановить; при сжатии **без потерь** они восстанавливаются точно. PCM и rawvideo обычно хранят данные без такого сжатия и занимают больше места.

История кодеков связана с задачами своего времени. H.261 и H.263 создавались для видеосвязи при скромной скорости канала; MPEG-1 и MPEG-2 помогли цифровому видео выйти на диски и в эфир. MP3 сделал практичным распространение музыки по сетям того времени. H.264 стал основой массового цифрового видео, HEVC предложил более плотное сжатие для высокого разрешения, а VP8, VP9 и AV1 развивались для сетевого видео. Новое поколение не отменяет старое: требования к устройствам, скорость кодирования и размер файла различаются. [История H.263: ITU](https://www.itu.int/rec/T-REC-H.263), [история MP3: Fraunhofer IIS](https://www.iis.fraunhofer.de/en/magazin/panorama/2025/30-years-of-mp3.html).

У видео важны также **профиль, уровень, битность и цветовой формат**. Два потока H.264 могут по-разному воспроизводиться на старом устройстве. У аудио имеют значение частота дискретизации и число каналов. Высокий битрейт не гарантирует качества: результат зависит от исходника, кодировщика и настроек. Повторное кодирование сжатого потока обычно добавляет потери, даже если новый файл больше.

В Media Unseal вариант «Исходный» сохраняет поддерживаемый поток без повторного кодирования. При выборе другого формата программа использует найденный путь обработки. Перечень кодировщиков зависит от установленного FFmpeg, а возможность записать выбранный кодек в конкретный контейнер проверяется отдельно. Декодер входного файла выбирает FFmpeg.

### 4.2. H.264 / AVC

**H.264**, он же **AVC** и MPEG-4 Part 10, — стандарт сжатия видео с потерями. Он широко применяется в камерах, трансляциях, MP4 и других контейнерах. Кодировщик сохраняет опорные кадры, а многие промежуточные описывает через отличия и движение. Это экономит место, но усложняет точный монтаж и перемотку. H.264 не равен MPEG-4 Part 2: схожие названия относятся к разным поколениям кодеков. [Спецификация H.264: ITU](https://www.itu.int/rec/T-REC-H.264-202108-S/en).

Главное практическое достоинство H.264 — распространённость воспроизведения. Но совместимость файла зависит также от профиля, уровня, разрешения, цвета, звука и контейнера. Профиль задаёт набор возможностей кодирования; уровень ограничивает сложность потока. Старый телевизор может понимать H.264, но не всякий его профиль или уровень.

В Media Unseal подтверждено копирование H.264 в MKV без изменения изображения. При конвертации может использоваться программный libx264 или доступный аппаратный кодировщик. Суффиксы nvenc, amf, qsv, vaapi обозначают реализации одного кодека. Запись имени в FFmpeg ещё не подтверждает работающее оборудование, драйвер или нужное сочетание настроек. Если исходный файл уже воспроизводится, повторное кодирование качества не прибавит.

### 4.3. H.265 / HEVC

**H.265**, или **HEVC**, — следующее поколение видеосжатия после H.264. Он может сохранить сопоставимое зрительное качество при меньшем битрейте, особенно на сложном видео высокого разрешения. Выигрыш зависит от сцены, исходника и настроек: единого процента экономии нет. Более гибкое разбиение изображения и предсказание повышают вычислительную сложность. [Спецификация HEVC: ITU](https://www.itu.int/rec/T-REC-H.265/e).

HEVC часто встречается в 4K, HDR и видеосъёмке современных устройств. Само название HEVC не означает HDR: важны битность, цветовые характеристики и метаданные. Старое устройство может не воспроизвести HEVC даже при поддержке контейнера MP4 или MKV; стоит проверить итоговый файл на целевом проигрывателе.

Media Unseal подтверждённо копирует HEVC в MKV без перекодирования. Для нового кодирования в исследованной сборке FFmpeg перечислены libx265 и аппаратные реализации; доступность конкретного пути зависит от системы. Переход с H.264 на HEVC занимает время и не восстанавливает уже потерянные исходником детали.

### 4.4. AV1, VP8, VP9

**VP8** стал видеокодеком раннего WebM; **VP9** развил его и предложил более эффективное сжатие и возможности для высокого разрешения. **AV1** — отдельный стандарт более нового поколения от Alliance for Open Media, а не очередная версия VP9. Все три обычно применяются для видео с потерями. [WebM Project](https://www.webmproject.org/about/), [обзор VP9: Google](https://developers.google.com/media/vp9), [выпуск AV1: AOMedia](https://aomedia.org/press%20releases/the-alliance-for-open-media-kickstarts-video-innovation-era-with-av1-release/).

| Кодек | Сильная сторона | Что проверить |
|---|---|---|
| VP8 | Совместимость с ранним WebM. | При сравнимом качестве часто требует больше данных, чем новые кодеки. |
| VP9 | Более плотное сжатие и распространение в веб-видео. | Поддержку декодирования на конечном устройстве. |
| AV1 | Современное эффективное сжатие, в том числе для высоких разрешений. | Время кодирования и аппаратную поддержку устройства. |

У этих сравнений нет универсального процентного результата: сцена, битрейт и настройки меняют картину. WebM — контейнер, а VP8 и VP9 — кодеки внутри него; AV1 встречается и в других контейнерах. AVIF использует кодирование изображения на основе AV1, но файл AV1-видео и изображение AVIF — разные задачи.

В Media Unseal подтверждено копирование VP8 и VP9 в WebM, AV1 — в MKV. Копирование сохраняет исходное качество. Для нового кодирования доступны лишь сочетания, которые обнаружены и проверены с установленным FFmpeg; список аппаратных реализаций сам по себе не обещает их работоспособности.

### 4.5. MPEG-4 Part 2 и другие

**MPEG-4 Part 2** — видеокодек, знакомый по файлам эпохи AVI и реализациям вроде Xvid. **MP4** — контейнер, а **H.264 / MPEG-4 Part 10** — другой кодек. MPEG-4 Part 2 обычно уступает современным решениям по соотношению размера и качества, но старые плееры и архивы могут опираться именно на него. Media Unseal подтверждённо копирует такой поток в AVI.

**H.263** появился раньше H.264 и был рассчитан на видеосвязь по каналам с небольшой пропускной способностью. В каталоге FFmpeg также есть H.261 и вариант H.263+ (h263p). Они важны для старых записей и узких требований совместимости. Наличие кодировщика H.263 в FFmpeg не означает подтверждённого отдельного маршрута копирования в Media Unseal. [Рекомендация H.263: ITU](https://www.itu.int/rec/T-REC-H.263).

**MPEG-1 Video** напоминает о ранних цифровых носителях; **MPEG-2 Video** широко применялся на DVD и в телевещании. Для MPEG-2 подтверждён вывод исходного потока в M2V. **ProRes** ориентирован на монтаж: обычно даёт крупные файлы, удобные для постобработки; подтверждено копирование в MOV. **FFV1** — кодек видео без потерь для хранения мастер-файлов и архивов; подтверждено копирование в MKV. H.266/VVC, EVC и AVS2 присутствуют в каталоге FFmpeg ниже, но подтверждённого маршрута программы для них нет. [FFV1: RFC 9043](https://datatracker.ietf.org/doc/html/rfc9043).

### 4.6. AAC, MP3, Opus

**MP3** закрепился как способ уменьшить музыкальный файл при приемлемом звучании. Его сильная сторона — совместимость с множеством старых проигрывателей, автомагнитол и бытовых устройств. Это сжатие с потерями: часть звуковой информации отбрасывается с учётом особенностей слуха. Высокий битрейт может сделать потери менее заметными, но не превратит MP3 в звук без потерь. [История MP3: Fraunhofer IIS](https://www.iis.fraunhofer.de/en/magazin/panorama/2025/30-years-of-mp3.html).

**AAC** — более позднее семейство сжатия звука с потерями. Оно распространено в MP4, телефонном видео и потоковых сервисах; при сопоставимых условиях часто эффективнее MP3. Профили AAC различаются, и старое устройство может понимать не каждый из них. AAC — кодек; M4A обычно обозначает аудиоконтейнер. Подтверждённый отдельный выход исходного AAC в Media Unseal — AAC/ADTS.

**Opus** создавался для широкого диапазона задач — от речи и связи с малой задержкой до музыки. Он приспосабливается к различным скоростям потока, но старое автономное оборудование может поддерживать его хуже, чем MP3 или AAC. В программе подтверждён отдельный выход исходного Opus. [Спецификация Opus: RFC 6716](https://datatracker.ietf.org/doc/html/rfc6716).

| Приоритет | Практический выбор |
|---|---|
| Старый проигрыватель | MP3 при поддержке его контейнера. |
| Видео для распространённых мобильных устройств | AAC вместе с подходящими видео и контейнером. |
| Современный сетевой звук или речь | Opus, если получатель его воспроизводит. |

Все три потока можно сохранять по подтверждённым маршрутам без повторного кодирования. Перевод MP3 в AAC или Opus не улучшает исходный звук: утраченное не возвращается, а новая компрессия может добавить искажения. Если нужно лишь извлечь дорожку, оставьте «Исходный».

### 4.7. AC3, E-AC3, DTS

**AC-3**, известный как Dolby Digital, — распространённый формат многоканального звука с потерями. Он встречается на дисках, в телевизионных записях и видеоконтейнерах. **E-AC-3**, или Dolby Digital Plus, развивает это семейство и рассчитан на более гибкую передачу многоканального звука, в том числе по сети. Поддержка AC-3 на устройстве ещё не гарантирует воспроизведение E-AC-3. [Dolby Digital Plus: Dolby](https://professional.dolby.com/technologies/dolby-digital-plus/).

**DTS** — отдельное семейство многоканального кодирования для домашнего кино и дисков. Название DTS в сведениях о потоке не раскрывает все варианты семейства: расширения и режимы вроде DTS-HD имеют собственные свойства. Сравнивать AC-3 и DTS по одному битрейту некорректно; важны мастер-запись, вариант кодека и воспроизводящее устройство.

Media Unseal подтверждённо копирует AC-3, E-AC-3 и DTS в отдельные файлы соответствующих форматов. Это сохраняет исходную структуру потока. Конвертация может изменить кодек, каналы и совместимость. Когда нужен, например, стереовыход для простого устройства, проверьте настройку каналов и результат воспроизведения.

### 4.8. FLAC, PCM и WAV

**PCM** представляет звук последовательностью измеренных отсчётов. Частота дискретизации, разрядность и число каналов определяют способ их записи и объём данных. Повышение частоты или разрядности готовой записи не добавляет отсутствующих деталей. PCM бывает целочисленным и с плавающей точкой; порядок байтов и упаковка различаются. Поэтому в каталоге FFmpeg так много вариантов PCM. [Кодеки PCM: FFmpeg](https://ffmpeg.org/ffmpeg-codecs.html).

**WAV** — контейнер, часто используемый для PCM. «Сохранить в WAV» описывает оболочку файла, а не единый кодек внутри. Несжатый PCM занимает много места, зато не вносит потерь от сжатия и удобен в монтаже. В Media Unseal подтверждён отдельный WAV для PCM s16le, s24le, s32le и f32le; это не распространяется автоматически на все варианты PCM из каталога.

**FLAC** сжимает PCM без потерь: после декодирования отсчёты восстанавливаются точно. Он обычно требует меньше места, чем несжатый PCM, но степень экономии зависит от записи. Media Unseal подтверждённо копирует FLAC в отдельный FLAC-файл. Перевод MP3 в FLAC не возвращает детали, утраченные в MP3: FLAC точно сохранит лишь декодированную версию. [Спецификация FLAC: RFC 9639](https://datatracker.ietf.org/doc/html/rfc9639).

**ALAC**, **WavPack** и **TTA** — другие способы сжатия звука без потерь. Для ALAC в программе подтверждён отдельный выход M4A. Выбор между ними обычно определяется требованиями устройства и контейнера, а не «лучшим» восстановленным звуком: при корректном декодировании исходные отсчёты должны совпадать.

### 4.9. Другие кодеки

Ниже сохранён **каталог кодеков и кодировщиков из исследованной сборки FFmpeg**. Это снимок возможностей конкретной сборки, а не перечень гарантированно работающих вариантов Media Unseal. В столбце статуса «Только FFmpeg» означает отсутствие подтверждённого маршрута копирования в приложении. Динамическая конвертация может предложить часть таких кодеков после проверки кодировщика и совместимости с контейнером; одно только присутствие в таблице результата не обещает.

**Как читать редкие названия.** Huffyuv, FFV1, Ut Video и MagicYUV относятся к семействам видео без потерь, востребованным в монтаже и архиве; rawvideo хранит кадры практически без кодекового сжатия, поэтому файлы велики. DNxHD, ProRes и CineForm (cfhd) связаны с производственным монтажом и обменом материалами. DV Video пришёл из цифровых видеокамер, Theora — из открытой веб-экосистемы, WMV и MSMPEG4 — из старых Windows-форматов, Sorenson и Cinepak — из раннего компьютерного видео. Совпадение цели не делает их взаимозаменяемыми: контейнеры, точность цвета и поддержка проигрывателей различаются.

**Телефония и специализированный звук.** AMR-NB и AMR-WB ориентированы на речь в мобильной связи; GSM, G.722, G.723.1, iLBC и Codec2 — другие речевые семейства с разными требованиями к связи. Speex также создавался для речи; Opus охватывает и речь, и музыку. Многочисленные ADPCM сжимают разницы между отсчётами и привязаны к конкретным устройствам или старым контейнерам: одинаковая приставка ADPCM не означает совместимость вариантов. A-law и μ-law относятся к телефонному PCM. aptX, aptX HD, SBC и LC3 связаны с передачей звука по беспроводным каналам; присутствие их кодировщиков в FFmpeg не превращает файл в готовую Bluetooth-передачу.

**Графика рядом с видео.** FFmpeg относит к видеокодекам и отдельные кадры: PNG, GIF, APNG, WebP, JPEG, TIFF и другие изображения. Здесь важнее понимать, статичен ли исходник и содержит ли последовательность кадров, чем ориентироваться только на техническую категорию FFprobe. Каталог графических кодировщиков не равен списку подтверждённых преобразований изображений в приложении. Подробнее о файлах и анимации — в темах 3.7 и 1.9.

### 4.10. Кодеки субтитров

Субтитры тоже имеют формат потока, хотя слово «кодек» здесь выглядит непривычно. Главное различие — **текст** или **изображения надписей**. Текстовые дорожки хранят символы и время показа; слова можно искать, копировать и переводить. Графические дорожки хранят готовые изображения надписей: простой сменой формата получить из них текст нельзя.

**SubRip / SRT** — простой текст с временными метками; он удобен для обмена, но почти не хранит оформление. **ASS / SSA** добавляют стили, позиционирование и эффекты. **WebVTT** ориентирован на веб-видео и допускает дополнительные указания для отображения. **mov_text** представляет текстовую дорожку в контейнерах семейства MP4/MOV; **TTML** описывает субтитры средствами XML. Конвертация между текстовыми форматами возможна, но не всё оформление переносится без изменений. [WebVTT: W3C](https://www.w3.org/TR/webvtt1/).

**PGS** — графические субтитры, знакомые по Blu-ray; **DVD Subtitle**, **DVB Subtitle** и **XSub** также графические. Их преимущество — сохранение готового изображения надписи; недостаток — невозможность обычного поиска и редактирования слов. Для превращения изображения в текст понадобилось бы распознавание символов (OCR), которого в Media Unseal нет. Поэтому графическая дорожка не предлагается как источник текстовой конвертации.

В Media Unseal подтверждены маршруты копирования SubRip в SRT, ASS/SSA в ASS, WebVTT в VTT и PGS в SUP. Другие текстовые выходы могут появляться после проверки установленного FFmpeg. Если нужно сохранить исходные надписи и оформление, сначала используйте «Исходный»; после текстового преобразования проверьте переносы строк, стили и время на нескольких репликах. Наличие кодировщиков dvdsub, dvbsub или xsub в FFmpeg не означает подтверждённого преобразования в них через приложение.

## 5. Технологии обработки

### 5.1. Копирование без перекодирования

**Копирование потока** — перенос уже закодированных видео, звука или субтитров в новый файл. Программа указывает FFmpeg конкретный поток источника и просит записать его без повторного кодирования. Кадры и звуковые отсчёты не пересчитываются, поэтому не возникает нового поколения потерь от сжатия. Обычно это быстрее конвертации: основная работа состоит в чтении и записи данных. Время всё же зависит от размера файла, накопителя и проверки результата. Структура выходного контейнера и часть служебных данных могут отличаться от исходного файла.

{{diagram:stream-copy}}

В интерфейсе это вариант **«Исходный — без перекодирования»**. Отметьте нужные потоки галочками слева от строк, оставьте для них исходный формат, выберите папку и нажмите **«Извлечь»**. Несколько отмеченных потоков сохраняются отдельными файлами. Оригинальный кодек, размер кадра, частота кадров, частота звука и каналы при таком извлечении сохраняются. Копирование само по себе не уменьшает качество и не исправляет дефекты исходного потока.

Контейнер должен принимать данный кодек. Например, нельзя получить произвольный MP4 из любого видеопотока, просто указав расширение .mp4. Если выбранный выход несовместим с исходным кодированием, нужен другой контейнер или декодирование с новым кодированием. Если цель — изменить разрешение, FPS, битрейт либо каналы, копирование также не подходит. В расширенных настройках может быть вариант **copy** для выбранного контейнера: программа проверяет совместимость; для видео окончательная проверка происходит при записи выходного файла. Переименование расширения проверку не заменяет.

Есть и тонкость: «без перекодирования» не всегда означает побайтово одинаковый файл. Новый контейнер получает собственные заголовки и временные метки; для некоторых видеопотоков могут потребоваться служебные изменения упаковки битового потока. Само сжатое изображение при этом не создаётся заново. Для вложений MKV действует отдельный путь: подтверждённые JPEG и PNG копируются собственным модулем приложения как байты вложенного файла.

### 5.2. Декодирование и кодирование

При **декодировании** сжатый поток превращается во внутреннее представление кадров или звуковых отсчётов. Затем фильтры и настройки, если они нужны, меняют размер изображения, частоту кадров или параметры звука. **Кодировщик** создаёт новый поток, а **мультиплексор** (muxer) записывает его в выходной контейнер. Так устроена конвертация; читать контейнер источника помогает демультиплексор (demuxer). Кодек определяет правила потока, контейнер — способ упаковать его вместе с другими сведениями. [Обзор обработки в FFmpeg](https://ffmpeg.org/ffmpeg.html).

{{diagram:transcode}}

Повторное кодирование требуется, когда исходный кодек несовместим с нужным контейнером либо вы меняете свойства самого потока. Выбрав в программе другой формат, вы получаете предложенный совместимый кодировщик; в расширенных настройках можете выбрать иной проверенный вариант. **«Обработать»** запускает такую конвертацию. Если в одной задаче часть дорожек выбрана в режиме «Исходный», они не перекодируются только из-за названия общей кнопки.

У сжатия с потерями есть цена: декодер не возвращает детали, удалённые прежним кодированием, а новый проход может отбросить дополнительные. Изменение формата ради совместимости бывает необходимо, но не «повышает качество» исходника. Пробная проверка кодировщика подтверждает лишь короткий тест на данной системе, а не любой реальный файл. После важной конвертации проверьте воспроизведение, продолжительность, звук, субтитры и нужные места изображения.

### 5.3. Программные кодировщики

**Программный кодировщик** выполняет расчёты главным образом на процессоре. Один кодек может иметь несколько реализаций: например, H.264 можно кодировать libx264, а для AV1 в исследованной сборке FFmpeg перечислены libaom-av1, librav1e и libsvtav1. Для звука встречаются libmp3lame и libopus. Различия между реализациями касаются скорости, доступных настроек и результата при конкретных параметрах; название кодека само по себе не выбирает «лучший» кодировщик для любой задачи.

В Media Unseal базовый список предлагает подходящий неаппаратный вариант для выбранного выходного формата. Кнопка **«Найти другие совместимые кодировщики»** проверяет дополнительные программные варианты коротким выводом. Программа проверяет, удаётся ли записать и прочитать тестовый файл. После выбора кодировщика поля качества, битрейта и других параметров остаются необязательными; CRF становится доступен лишь при подтверждённой поддержке. Итоговый файл зависит от исходника и настроек, поэтому тестовый результат не заменяет проверки самого экспорта.

Высокая загрузка CPU при кодировании ожидаема. Более медленный программный кодировщик иногда позволяет получить меньший файл при сопоставимом видимом качестве, но это не универсальное правило и не обязательство конкретного имени. Для единичного файла ориентируйтесь на нужную совместимость и результат просмотра; для серии файлов сначала попробуйте один небольшой образец.

### 5.4. Аппаратные кодировщики

**Аппаратное кодирование** переносит часть работы на специализированные блоки видеокарты или процессора. В FFmpeg могут встречаться реализации NVIDIA NVENC, Intel QSV, AMD AMF, VAAPI, VideoToolbox, Vulkan и D3D12VA. Они могут заметно ускорить создание видео, но скорость и качество зависят от поколения оборудования, драйвера, кодека и настроек. Имя аппаратного кодировщика в списке FFmpeg ещё не доказывает, что он запустится на текущем компьютере.

В окне настроек видео кнопка **«Найти доступные аппаратные кодировщики»** запускает короткую пробную запись для выбранного формата. Результаты поиска относятся к текущей машине и этому сочетанию контейнера с кодеком. Программа проверяет тестовый выход, а для видео также пробует его декодировать. Найденный вариант можно выбрать как кодировщик и применить настройки. Если он не найден, проверьте установленный FFmpeg, драйвер и поддержку нужного кодека оборудованием; программный вариант остаётся возможным при наличии подходящего кодировщика.

**Аппаратное кодирование не означает полностью аппаратную цепочку обработки.** В текущем интерфейсе нет универсального режима аппаратного декодирования и GPU-фильтров. Поэтому даже при аппаратном кодировщике часть обработки может выполняться на CPU. Реализация h264_mf может присутствовать в FFmpeg, но текущая кнопка аппаратного поиска не относит её к своим аппаратным вариантам. [Аппаратное ускорение в документации FFmpeg](https://ffmpeg.org/ffmpeg.html#Hardware-acceleration).

### 5.5. Битрейт и качество

**Битрейт** показывает, сколько данных поток расходует за секунду; его обычно указывают в кбит/с или Мбит/с. При постоянном битрейте 1 Мбит/с минутный видеопоток занимает примерно 7,5 МБ без учёта звука и служебных данных. Это приблизительная оценка: фактический размер зависит от длительности, колебаний битрейта и контейнера. Общий битрейт файла складывается из видео, звука и остальных потоков. Поэтому два ролика одинаковой длительности и видеобитрейта могут иметь разный общий размер.

При сжатии **с потерями** кодировщик распределяет ограниченный объём данных между кадрами или звуковыми фрагментами. Поднять битрейт — значит дать ему больше места для деталей, движения и сложных сцен. Однако качество не измеряется одним числом: важны исходник, разрешение, FPS, кодек, настройки, количество повторных кодирований и условия просмотра. Низкий битрейт может проявиться блоками, размазыванием деталей, полосами на градиентах или слышимыми искажениями. Очень высокий битрейт может почти не дать заметной пользы, но увеличить файл.

**CRF** — режим управления качеством, если конкретный видеокодировщик его поддерживает. Вы задаёте степень сжатия, а кодировщик расходует больше данных на сложные фрагменты и меньше на простые. Для многих распространённых программных кодировщиков меньшее число CRF означает меньше потерь и больший файл, но одинаковое число у разных кодеков не означает одинаковое качество. CRF не является процентом. В Media Unseal поле включается только после проверки поддержки выбранным кодировщиком.

**Битрейт** удобен, когда есть предел размера или требования площадки; **CRF** — когда важнее ровное воспринимаемое качество при неизвестном заранее размере. Обычно начните с одного из этих способов, создайте короткий образец сложного фрагмента и оцените его на целевом экране. Для аудио отдельное поле «Качество, 0–10» передаёт параметр кодировщику: направление и смысл этой шкалы зависят от реализации, поэтому это не десятибалльная оценка записи. При копировании без перекодирования ни CRF, ни битрейт нового кодирования не применяются.

**Сжатие без потерь** восстанавливает исходные данные после декодирования, но не делает новый файл обязательно маленьким. Перекодирование MP3 в FLAC или H.264 в FFV1 лишь сохраняет уже декодированную версию — прежние потери не исчезнут. Для сохранения именно исходного кодированного потока используйте «Исходный».

### 5.6. Разрешение и FPS

**Разрешение** — число пикселей по ширине и высоте кадра. Запись 1920 × 1080 означает 1920 точек в каждой строке и 1080 строк; всего чуть больше двух миллионов пикселей на кадр. Чем больше пикселей, тем больше деталей *может* вместить изображение и тем больше данных приходится обрабатывать. Но увеличение 640 × 360 до 1920 × 1080 не создаёт деталей, которых не было в источнике. Важны также резкость съёмки, сжатие и размеры экрана.

**Кадр** — отдельное изображение в последовательности видео. **FPS** происходит от английского *frames per second* — «кадров в секунду». При 25 кадр/с за секунду показываются примерно 25 изображений; при 50 — примерно 50. Частота влияет на плавность движения и количество кадров, которые нужно кодировать. Встречаются целые и дробные значения: например, 24 и 25, 30 и 60, а также приблизительно 23,976 или 29,97 кадр/с. Универсально «лучшей» частоты нет: она зависит от источника, способа съёмки и требований воспроизведения.

Если при конвертации снизить FPS, часть кадров будет отброшена; если повысить, FFmpeg может повторить соседние кадры. Это не создаёт новые моменты движения, как при настоящей съёмке с более высокой частотой. Резкое снижение способно сделать движение прерывистым. Изменение FPS также может повлиять на длительность или синхронизацию в сложных источниках, поэтому проверьте результат. В Media Unseal задавайте выходную частоту в настройках видео; оставьте поле пустым, если менять движение не требуется.

При уменьшении разрешения кадры масштабируются и часть мелких деталей теряется. Увеличение лишь пересчитывает пиксели. Если заполнить только ширину или только высоту, программа просит FFmpeg рассчитать вторую величину с сохранением пропорций; если вручную задать обе в ином соотношении, изображение может растянуться. Некоторым кодировщикам нужны кратные размеры, поэтому итог может быть округлён. При «Исходном» разрешение и FPS остаются прежними.

### 5.7. Частота дискретизации и каналы

Цифровой звук состоит из **отсчётов** — измерений звукового сигнала во времени. **Частота дискретизации** показывает, сколько отсчётов каждого канала приходится на секунду: 44 100 Гц означает 44 100 отсчётов в секунду, 48 000 Гц — 48 000. Эти значения часто встречаются в музыке и видео соответственно. Более высокая частота сама по себе не гарантирует слышимо лучшего результата: важны качество записи, обработка и оборудование. Пересчёт готового звука на более высокую частоту не восстанавливает отсутствующие частоты.

**Канал** — отдельный звуковой сигнал. Моно содержит один канал, стерео — два; многоканальные записи могут содержать центр, окружение и низкочастотный канал. Обозначение 5.1 обычно означает пять основных каналов и один низкочастотный, но одного числа «6» недостаточно для уверенного описания фактической раскладки: важен порядок и назначение каналов в потоке. На совместимость влияют и кодек, и контейнер, и возможности проигрывателя.

Если при конвертации уменьшить число каналов, FFmpeg сводит несколько входных сигналов в меньшее количество выходных. Такое сведение меняет пространственное звучание; слишком тихий голос или перекос каналов нужно проверять на слух. Увеличение количества каналов не создаёт независимую многоканальную запись. Изменение частоты пересчитывает отсчёты и может ограничить верхнюю часть частотного диапазона. В настройках аудио Media Unseal эти поля необязательны; для сохранения исходных параметров используйте «Исходный».

### 5.8. Метаданные и языки

**Метаданные** — сведения о файле и его потоках помимо самого изображения, звука или текста субтитров. Они могут включать название, исполнителя, дату, комментарий, название дорожки, язык, технические параметры и служебные признаки. Часть параметров, например кодек и размер кадра, описывает устройство потока; часть представляет собой обычные теги, записанные автором файла. Теги могут отсутствовать, быть неточными или устареть после обработки.

Язык дорожки — обычно **метка в метаданных**, а не результат автоматического распознавания речи. По ней удобно отличать озвучку и субтитры, но метка может быть ошибочной. FFprobe передаёт программе найденные теги и свойства, которые показываются в таблице и окне свойств потока. При включённой группировке Media Unseal раскладывает аудио и субтитры по языковым папкам; язык также может использоваться при формировании безопасного имени файла. Если метки нет, программа не определяет язык достоверно по содержимому.

Флажок **«Сохранять метаданные»** управляет переносом исходных тегов при экспорте. Он не превращает Media Unseal в редактор метаданных: программа не предлагает вручную исправлять названия, языки и прочие теги. Не все контейнеры поддерживают одинаковые поля; поэтому после изменения формата отдельные сведения могут не перенестись. Если метаданные важны для архива, проверьте свойства итогового файла.

### 5.9. Модуль извлечения вложений

В MKV могут находиться **вложения** — отдельные файлы, помещённые внутрь контейнера, например обложки, шрифты или другие сопутствующие материалы. Они отличаются от видеодорожки и от кадра, извлечённого из видео. Media Unseal показывает найденные вложения отдельно и позволяет выбрать их в окне вложений: по одному, несколько или все сразу, в том числе вместе с другими потоками в общей очереди.

Для подтверждённых **JPEG и PNG** программа использует собственный модуль на C#. Он читает структуру Matroska/EBML, находит раздел вложений, сопоставляет имя, тип файла и порядок с данными FFprobe и копирует выбранное изображение исходными байтами. Это не декодер видео и не кодировщик картинки: качество вложенного JPEG или PNG не меняется. Для предпросмотра чтение ограничено по размеру; при экспорте больших вложений данные читаются частями, без необходимости загружать весь файл в память.

{{diagram:matroska-attachments}}

Модуль проверяет границы данных и то, не изменился ли исходный файл после анализа. Если соответствие вложения неоднозначно, структура повреждена или данные выходят за пределы файла, операция прерывается вместо выбора «похожего» объекта. Подтверждённый маршрут относится к JPEG/PNG; наличие иных вложений в MKV не означает, что программа умеет извлекать их тем же путём. Это специализированный модуль вложений, а не универсальный редактор Matroska. [Структура вложений Matroska](https://www.matroska.org/technical/attachments.html).

### 5.10. Как устроены FFmpeg и FFprobe

**FFprobe** отвечает на вопрос «что находится в файле?». Он открывает источник и возвращает сведения о контейнере и потоках: тип, кодек, индексы, длительность, размер кадра, FPS, параметры звука, язык, теги и признаки дорожек, если они есть. Media Unseal запрашивает машиночитаемый JSON и на его основе заполняет таблицу потоков, свойства и доступные действия. Анализ не является полным просмотром всего фильма кадр за кадром; повреждённые участки могут обнаружиться позднее, во время обработки. [Документация FFprobe](https://ffmpeg.org/ffprobe.html).

**FFmpeg** выполняет основную обработку. При копировании он читает выбранный поток и записывает его в совместимый контейнер. При конвертации декодирует вход, при необходимости применяет преобразования и передаёт результат кодировщику. Также FFmpeg используется для некоторых операций с изображениями и получения кадров предпросмотра. Media Unseal формирует параметры задачи, следит за ходом, отменой и ошибками, показывает сообщения в журнале и Diagnostic Report. Собственный модуль вложений MKV — отдельный специализированный путь.

{{diagram:components}}

При первом запуске программа проверяет наличие и работоспособность **обоих** инструментов. Список выходных форматов и кодировщиков считывается из установленного FFmpeg, поэтому на другой машине он может отличаться. Затем программа отбирает подходящие для своих сценариев варианты и проверяет отдельные сочетания короткими пробными операциями. Успешная проба означает, что сочетание сработало в этих условиях; она не обещает успеха с каждым исходником, сложным профилем или повреждённым файлом. [Форматы FFmpeg](https://ffmpeg.org/ffmpeg-formats.html), [кодировщики FFmpeg](https://ffmpeg.org/ffmpeg-codecs.html).

В диагностическом отчёте можно увидеть сведения, полезные для разбора отказа: этап операции, проверку сочетания, сообщение FFmpeg и итог. Это помогает отличить неподдерживаемую пару кодек–контейнер от проблемы конкретного файла. FFmpeg и FFprobe — внешние инструменты; версия, состав сборки, драйверы и оборудование напрямую влияют на доступные варианты обработки.

## 6. Справочные материалы

### 6.1. Основные термины

Этот словарь нужен для быстрого поиска. Подробные объяснения контейнеров, кодеков и обработки находятся в разделах 3–5.

| Термин | Короткое значение |
|---|---|
| **Медиафайл** | Файл с изображением, звуком, субтитрами и служебными сведениями. |
| **Контейнер** | Упаковка для потоков и метаданных: например, MKV, MP4 или WAV. |
| **Расширение** | Окончание имени файла после точки; подсказка о типе, но не доказательство внутреннего кодека. |
| **Поток / дорожка** | Отдельные видео, звук, субтитры, изображение или другой элемент внутри контейнера. |
| **Индекс потока** | Номер, по которому программа выбирает конкретную дорожку источника. |
| **Кодек** | Правила записи и чтения содержимого потока, например H.264 или FLAC. |
| **Кодировщик / декодер** | Реализация, которая создаёт / читает поток данного кодека. |
| **Профиль / уровень** | Набор возможностей кодека / ограничение сложности потока для оборудования. |
| **Сжатие с потерями** | Уменьшение объёма с необратимым удалением части информации. |
| **Сжатие без потерь** | Уменьшение объёма с точным восстановлением исходных данных после декодирования. |
| **Копирование потока** | Запись исходного кодированного потока в совместимый выход без нового кодирования. |
| **Конвертация / перекодирование** | Декодирование источника и создание нового потока кодировщиком. |
| **Демультиплексор / мультиплексор** | Компонент, который читает потоки из контейнера / записывает их в контейнер. |
| **Битрейт** | Объём данных, приходящийся на секунду потока; обычно кбит/с или Мбит/с. |
| **Постоянный / переменный битрейт** | Расход данных с заданным приблизительным темпом / с изменением по сложности материала. |
| **CRF** | Параметр управления степенью сжатия и качеством у поддерживающих его видеокодировщиков. |
| **Пиксель** | Элемент цифрового изображения. |
| **Глубина цвета** | Число бит, отведённых на представление цветовых значений; не то же самое, что разрядность звука. |
| **Альфа-канал** | Данные о прозрачности изображения, если формат и обработка их поддерживают. |
| **Разрешение** | Ширина × высота изображения в пикселях. |
| **Кадр** | Отдельное изображение в последовательности видео или анимации. |
| **Ключевой кадр** | Кадр, от которого можно начинать восстановление последовательности без предыдущих кадров. |
| **FPS** | Frames per second, число кадров за секунду. |
| **Переменная частота кадров** | Последовательность, где временные интервалы между кадрами различаются. |
| **Частота дискретизации** | Число звуковых отсчётов в секунду для каждого канала, измеряется в герцах. |
| **Разрядность звука** | Способ представления точности каждого PCM-отсчёта; не показатель качества исходной записи сам по себе. |
| **Канал** | Отдельная звуковая составляющая, например левая или правая в стерео. |
| **Сведение каналов** | Пересчёт многоканального звука в меньшее число выходных каналов. |
| **PCM** | Представление звука как последовательности отсчётов. |
| **Метаданные / теги** | Сведения о файле и потоках: названия, языки, даты и другие поля. |
| **Языковая метка** | Записанное в файле обозначение языка дорожки; может отсутствовать или быть ошибочным. |
| **Вложение MKV** | Самостоятельный файл внутри Matroska, например обложка или шрифт. |
| **MIME-тип** | Обозначение типа вложенного файла, например image/jpeg. |
| **Обложка / постер** | Изображение, связанное с медиафайлом; может быть вложением или отдельным потоком. |
| **Текстовые / графические субтитры** | Символы с временными метками / готовые изображения надписей. |
| **OCR** | Распознавание символов на изображениях; в Media Unseal не реализовано. |
| **FFprobe** | Инструмент анализа контейнера и потоков. |
| **FFmpeg** | Инструмент копирования, конвертации и части операций с изображением. |
| **Diagnostic Report** | Подробная история событий и ошибок для разбора проблемы. |

### 6.2. Таблица совместимости

**Совместимость состоит из нескольких проверок:** программа должна распознать исходный поток, выходной контейнер должен принимать выбранный кодек, FFmpeg должен иметь нужный кодировщик при конвертации, а конечное устройство — уметь воспроизвести результат. Фраза «поддерживается MP4» говорит только о контейнере. Точный ответ для конкретного файла зависит также от профиля, уровня, разрешения, каналов и состояния источника.

Ниже — **подтверждённые маршруты сохранения исходного потока** в Media Unseal. Это не таблица всех теоретических сочетаний FFmpeg. У видео из распознанного исходного контейнера программа также может сохранить тот же контейнер; если он не подходит или не распознан, используется маршрут по кодеку.

| Исходный поток | Отдельный выход без перекодирования | На что обратить внимание |
|---|---|---|
| H.264, HEVC, AV1, FFV1 | MKV | Кодек остаётся исходным; воспроизведение зависит от проигрывателя. |
| VP8, VP9 | WebM | WebM принимает эти кодеки; сам контейнер качества не меняет. |
| MPEG-2 Video | M2V | Отдельный видеопоток без исходного звука. |
| MPEG-4 Part 2, MJPEG-видео | AVI | Не путать MPEG-4 Part 2 с H.264 и контейнером MP4. |
| ProRes | MOV | Большой объём типичен для монтажного материала. |
| AAC, MP3, FLAC, Opus, Vorbis | AAC, MP3, FLAC, Opus, OGG соответственно | AAC выводится как ADTS; расширение не определяет качество. |
| AC-3, E-AC-3, DTS | AC3, EAC3, DTS | Многоканальный звук сохраняется как исходный поток. |
| PCM s16le, s24le, s32le, f32le | WAV | Иные разновидности PCM не входят в этот подтверждённый маршрут. |
| ALAC | M4A | Кодек остаётся ALAC. |
| SubRip, ASS/SSA, WebVTT, PGS | SRT, ASS, VTT, SUP соответственно | PGS — графический поток; текст в нём не распознаётся. |
| Статические JPEG, PNG и некоторые другие распознанные изображения | Соответствующий исходный формат | Доступность определяется типом конкретного потока. |
| GIF, APNG, анимированный WebP | Соответствующий исходный формат | Речь о сохранении распознанной анимации без превращения её в статичный кадр. |
| Вложения JPEG/PNG в MKV | JPG/PNG | Собственный модуль копирует подтверждённое вложение как файл. |

Для отдельного аудиофайла с распознанным контейнером программа в ряде случаев сохраняет именно его исходный контейнер, а не запасной выход из таблицы. Это касается, например, подходящих WAV, OGG, CAF, AIFF и M4A. Таблица описывает основной маршрут извлечения дорожки из другого файла; фактический выход показывается в интерфейсе.

**Когда нужен другой формат.** Media Unseal строит список выходов по установленному FFmpeg и предлагает подходящий кодировщик. Для видео рассматриваются, в частности, MP4, MKV, MOV, WebM, AVI, MPEG-TS, MPEG, NUT, ASF, FLV, OGV, 3GP, 3G2 и MXF; для анимации — GIF, APNG, WebP; для звука и текстовых субтитров свои наборы. Наличие формата в каталоге ещё не значит, что любой входной кодек можно скопировать туда без изменений или что любой кодировщик с ним сработает. Программа проверяет выбранную комбинацию, а результат реального экспорта проверяет FFmpeg. Полные каталоги контейнеров, изображений и кодеков даны в темах 3.5–3.7 и 4.9.

| Цель | С чего начать | Если не подходит |
|---|---|---|
| Получить оригинальную дорожку | «Исходный» и подтверждённый контейнер. | Выбрать другой совместимый контейнер. |
| Воспроизвести на определённом устройстве | Узнать его требования к контейнеру, видео и звуку. | Конвертировать в поддерживаемое сочетание и проверить файл на устройстве. |
| Уменьшить размер | Проверить битрейт и качество исходника. | Настроить кодек и качество; сравнить образец, учитывая новые потери. |
| Сохранить исходное качество сжатого потока | Копировать без перекодирования. | Если требуется новый формат, оценить неизбежный компромисс. |

### 6.3. Частые вопросы

**Почему в списке есть формат, но обработка не начинается?** Список показывает найденный выход FFmpeg. Кодировщик, контейнер и параметры должны пройти проверку вместе. Сообщение программы и Diagnostic Report уточнят, на каком шаге сочетание не подошло.

**Почему файл с расширением MP4 не воспроизводится на устройстве?** Расширение описывает контейнер, а внутри могут быть разные видео- и аудиокодеки, профили и каналы. Проверьте свойства обоих потоков и требования устройства.

**Что выбрать, если нужно лишь достать звук без изменений?** Отметьте нужную аудиодорожку, оставьте «Исходный» и извлеките её. Если хотите получить другой кодек, потребуется конвертация.

**Можно выбрать сразу несколько языков?** Да, отметьте нужные аудио- или субтитровые дорожки. Они сохраняются отдельными файлами; языковые папки можно включить в настройках. Программа не собирает из выбранных дорожек новый общий фильм.

**Почему новый файл больше исходного?** Другой кодек, более высокий битрейт, несжатый PCM или формат без потерь могут увеличить объём. Больший файл не доказывает улучшение исходного качества.

**Можно сделать звук лучше, переведя MP3 в FLAC?** Нет. FLAC сохранит без новых потерь уже декодированный MP3, но удалённые прежде детали не восстановит.

**Почему CRF неактивен или аппаратный кодировщик не найден?** Поддержка CRF проверяется для выбранного кодировщика. Аппаратный поиск зависит от FFmpeg, драйвера и оборудования; другой формат или программный кодировщик может оказаться доступным.

**Можно получить SRT из PGS или кадр из GIF одним выбором формата?** OCR для графических субтитров нет. Извлечение одного статичного кадра из анимированного GIF как отдельная функция не заявлено; не путайте его с сохранением самой анимации.

**Можно ли сохранить GIF, APNG или анимированный WebP без перекодирования?** Для распознанных анимационных потоков есть исходные маршруты. Создание короткого GIF из видео также проверено вручную; это не подтверждает все возможные варианты анимации и входных файлов.

**Что делать, если анализ прошёл, а экспорт завершился ошибкой?** Сначала посмотрите статус строки и журнал, затем откройте Diagnostic Report. Проверка коротким образцом не гарантирует, что весь реальный файл цел и что выбранный контейнер примет каждую его особенность.

### 6.4. Ограничения программы и обратная связь

Media Unseal обрабатывает **один исходный файл за раз** и сохраняет выбранные потоки отдельными результатами. Она не собирает из них новый общий фильм. Подтверждённый собственный путь для вложений MKV ограничен JPEG и PNG. Графические субтитры не превращаются в текст: OCR нет. Универсальный пользовательский режим аппаратного декодирования и GPU-фильтров не реализован. Набор выходов и кодировщиков зависит от установленного FFmpeg, драйверов и оборудования.

Каталоги в справочнике различают **подтверждённые маршруты программы**, **динамические кандидаты конвертации** и **возможности, перечисленные только FFmpeg**. Наличие кодировщика не доказывает работоспособность с любым контейнером или источником. Исследованная локальная сборка дала большой список выходов после разбора каталога, но не все сочетания были испытаны. Отдельные реальные файлы могут содержать повреждённые данные, необычные метаданные или несовместимые профили. При ошибке начните с статуса потока, журнала и Diagnostic Report; проверьте доступность папки назначения и состояние FFmpeg/FFprobe.
